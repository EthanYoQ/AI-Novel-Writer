# AI 小说作家 1.1.0

## 新功能

1. 角色动态状态现在区分作者输入、模型提炼和旧项目未知来源，并让模型提炼内容回到对应定稿原文后再用于后续写作。
2. 章节材料现在把作者任务、尚未发生的计划、定稿历史和未定稿候选稿分开呈现，并保留相关原文的相邻段落以减少因果、否定和物品转交信息的遗漏。
3. 连续草稿模式现在沿用本次批次实际保存的候选稿版本和正文，不再把候选稿冒充定稿历史或只保留上一章结尾。
4. 材料预算不足或可选来源无法定位时会记录覆盖缺口；作者明确的本章任务和硬性要求不会被静默丢弃。
5. 审稿现在逐项展示本章关键事件是否完成，并附上正文证据，帮助发现只做准备或推迟完成的情况。
6. 证据不足的审稿项现在标为“待核实”，本章目标的处理均由作者明确选择，避免模型误判直接引发修稿。

这些来源边界可降低错误摘要和过期状态污染后续章节的风险，但不保证模型输出完全没有漂移，也不保证每章字数都达到目标。

## 修复

1. 修复了下载进行期间被排队的更新检查覆盖已确认版本或重复调用更新源的问题。
2. 修复了拆分 Markdown 导出复用旧目录而可能混入上次残留章节的问题。
3. 修复了工作流完成通知按第一个空格截断完整标题的问题。
4. 大纲现在按指定章节范围分批生成，中断后可恢复或继续下一批，并保留已确认章节。
5. 规划结果格式损坏或被截断时，可以在原有调用预算内缩小批次恢复，减少整批重做。
6. 审稿报告格式不符合要求时可以在原有预算内重建一次，再次失败不会保存为有效报告。

## 保留自 1.0.0 的功能

1. 写作 Skill 现在可以独立安装，并按规划、正文、审稿或润色阶段分别使用。
2. 故事线视图现在会展示主线和支线的进度，并可快速跳到对应章节依据。
3. 规划资料现在可以导入项目，帮助蓝图和后续写作保持同一套设定。
4. 角色表现在只接收蓝图中明确确认的新角色，并持续记录角色状态。
5. 从蓝图、草稿到审稿、修订和定稿的中文长篇写作流程现在衔接得更完整。
6. Windows 和 macOS 用户现在都能在应用内查看并启动适合本机的更新。

## 保留自 1.0.0 的修复

1. 修复了同时编辑多个草稿时，后台保存可能写错页面或在关闭后继续写入的问题。
2. 修复了旧请求结果可能覆盖较新蓝图、草稿、审稿或修订内容的问题。
3. 修复了中断后的恢复记录无法可靠确认原始草稿，或继续写作时使用过期来源的问题。
4. 修复了导出时可能混入未定稿、过期或不匹配章节内容的问题。
5. 修复了 Windows 安装和升级检查把正常的辅助进程退出误判为失败的问题。

## 发布目标与安装提示

同一冻结源码的七项资产合同覆盖 Windows x64、macOS ARM64 和 macOS x64：`ai-novel-writer-setup-1.1.0.exe`、`ai-novel-writer-setup-1.1.0.exe.blockmap`、`latest.yml`、`ai-novel-writer-mac-arm64-1.1.0-installer.dmg`、`ai-novel-writer-mac-arm64-1.1.0-installer.dmg.sha256`、`ai-novel-writer-mac-x64-1.1.0-installer.dmg` 与 `ai-novel-writer-mac-x64-1.1.0-installer.dmg.sha256`。

Windows 安装包未代码签名，首次安装时系统可能显示 SmartScreen 提示；macOS 安装包采用 ad-hoc 签名且未公证，首次打开时可能需要在系统设置中手动确认。

# AI Novel Writer 1.1.0

## New features

1. Character progress now distinguishes author input, model-derived state, and legacy data with unknown provenance, and derived material returns to its finalized source prose before it is used for later writing.
2. Chapter materials now separate the author task, future plans, finalized history, and unfinalized candidate drafts while retaining adjacent source paragraphs that may carry causality, negation, or item transfers.
3. Review-draft batches now continue from the exact saved candidate draft IDs, versions, and prose selected in the current run instead of treating candidates as finalized history or keeping only the previous ending.
4. When optional material exceeds the budget or cannot be located, the app records the coverage gap instead of silently dropping the chapter's explicit task or hard requirements.
5. Reviews now show whether each chapter event is completed, with source excerpts to help identify actions that were only prepared or postponed.
6. Review items with insufficient evidence are now marked as needing verification, and chapter-goal items require explicit author selection so model misjudgments do not directly trigger revision.

These source boundaries reduce the risk of a mistaken summary or outdated state contaminating later chapters, but they do not guarantee drift-free prose or perfect target-length compliance.

## Fixes

1. Fixed queued update checks that could replace an already confirmed version or call the update source again while a download was in progress.
2. Fixed split Markdown exports that could reuse an old directory and include chapters left by an earlier export.
3. Fixed workflow-completion notifications that could truncate a full title at its first space.
4. Outlines now generate within selected chapter ranges, preserve confirmed chapters, and support recovery or continuation with the next batch.
5. Malformed or truncated planning results can recover through smaller batches within the existing call budget, reducing whole-batch rework.
6. A malformed review report can be rebuilt once within the existing budget, and a second failure is not saved as a valid report.

## Retained from 1.0.0

1. Writing Skills can now be installed independently and used separately for planning, drafting, review, or polishing.
2. The story map now shows main and side-story progress and lets you jump to the supporting chapter.
3. Planning material can now be imported into a project so blueprints and later writing follow the same source material.
4. The character roster now adds only explicitly confirmed blueprint characters and keeps their status up to date.
5. The Chinese long-form workflow now connects blueprints, drafts, reviews, revisions, and final chapters more smoothly.
6. Windows and macOS users can now view and start the update intended for their computer from inside the app.

## Fixes retained from 1.0.0

1. Fixed background saves that could target the wrong page or continue after a draft was closed while editing multiple drafts.
2. Fixed older requests that could overwrite newer blueprint, draft, review, or revision content.
3. Fixed recovery records that could lose their source draft identity or continue from an outdated source.
4. Fixed exports that could include unfinished, outdated, or mismatched chapter content.
5. Fixed Windows install and upgrade checks that could mistake a normal helper-process exit for a failure.

## Release targets and installation notice

The seven-asset contract from one frozen source covers Windows x64, macOS ARM64, and macOS x64: `ai-novel-writer-setup-1.1.0.exe`, `ai-novel-writer-setup-1.1.0.exe.blockmap`, `latest.yml`, `ai-novel-writer-mac-arm64-1.1.0-installer.dmg`, `ai-novel-writer-mac-arm64-1.1.0-installer.dmg.sha256`, `ai-novel-writer-mac-x64-1.1.0-installer.dmg`, and `ai-novel-writer-mac-x64-1.1.0-installer.dmg.sha256`.

The Windows installer is not code-signed, so SmartScreen may appear during the first installation. The macOS installers are ad-hoc signed and not notarized, so the first launch may require manual confirmation in System Settings.
