# 本章目标逐项审稿与前端适配

对应 Issue #205；本轮实现起点 `ad75fc302bffee4e45d913a819e4c6e5cee59de7`。用户已批准同步改造前端、完成测试和独立审查后提交 GitHub PR，并在现有 PR 审查通过后合并、完成三平台资格与 1.1.0 发布。

## 产品行为

- 从当前章节蓝图的明确关键事件冻结目标原文及标识；章节目的作为背景，不自动变成额外任务。未来章节计划不变成本章必须完成的行动，本章仅要求作出安排时允许安排完成。
- 在现有审稿请求中逐项返回已完成、未完成或待核实，附对应正文引文。模型不能删除、改写或合并软件冻结的目标，以此掩盖未完成项。
- 缺失结果、重复标识、错误状态、无法定位的引文以及不可用的目标来源保持待核实；没有配置目标与读取失败明确区分。引文存在不等于语义判断正确。
- 使用既有审稿报告存储结构的扩展字段，不建立第二套事实库，不改正文、角色事实、定稿收据或自动定稿的授权边界。不为本功能新增默认 API 调用、语义重试或整章重写。
- 复用现有审稿列表展示目标、状态与证据；待核实不计通过。目标类未完成与待核实均不默认纳入修稿，作者须明确选择处理；普通连续性问题维持既有默认行为。人工确认快照保持不可变来源和历史兼容。
- 保留现有通用连续性审稿；本功能不宣称解决全部时间线、人物漂移或字数问题。

## 合同与职责

报告扩展 `goalReview`：version、chapterNumber、coverage、items。每项目标保留软件冻结的 id/text，状态为 completed/unmet/unknown，证据记录 quote/start/end。coverage 仅描述目标来源及逐项覆盖，不等于全部语义通过。

目标结果确定性投影到原审稿 items 并附 goalId，分别对应 pass/error/unknown；前端按 goalId 关联原结构，避免两套独立可编辑目标。待核实与“改进建议”分开。

后端切片拥有共享目标合同与审稿命令；前端切片拥有审稿报告和人工确认快照；主线程负责集成、规格与证据、完整验证、现有 PR 合并及发布决策。并行修改不得覆盖现有工作。

## 验收

1. 目标冻结、逐项覆盖、遗漏/重复/改写、伪造引文、未知状态、无配置与读取失败的中文回归。
2. 生产审稿命令同一请求、持久化报告、取消/切项目保护回归。
3. 真实浏览器验证三态、证据、目标类未完成和待核实默认不修稿、显式选择、确认后重开及旧报告兼容。
4. 使用本机已授权模型与合成中文材料验证本章任务延期和合理未来安排；原始正文与密钥不进入公开证据。机械通过、语义通过和文学质量分开报告，不修改已冻结 gold 来获得通过。
5. 固定提交执行 code-review 的 Standards/Spec 独立双轴；未通过项目不宣称通过。
