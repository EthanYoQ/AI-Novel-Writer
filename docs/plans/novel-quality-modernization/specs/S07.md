### 范围与替代关系

- 本轮完善“高级设置 → 通用 OpenAI 协议”。各厂商的兼容地址共用一条路径。
- Gemini 通过兼容地址使用时也走该路径。本轮不新增厂商原生协议，也不新增大批预设型号。
- 本节取代 C01、原 S07 及其消费者中的冲突准入解释。
- 移除的是“主机或型号未登记，就禁止生成”的限制。内置资料只辅助规划与参数转换。
- 来源准入、作者值、保存恢复和根预算保护继续有效。实验配置登记只约束对应实验。
- 原冻结规格、历史 FAIL/UNKNOWN 和物理账本保留原解释。不得追溯改判。

### S07.M01 — 移除 V3 型号白名单

1. 端点列表可选型号和手工填写的兼容型号均可使用。未命中内置资料不能成为拒绝调用的唯一理由。
2. 首次生成、细纲、正文、审稿、修稿及正常后续步骤使用共同规则。不能只放开设置页或首个请求。
3. 不得仅因未知容量或无法证明总费用硬上限而拒绝通用调用。不得因此触发 `GENERATION_MODEL_CAPABILITY_UNKNOWN` 或 `GENERATION_LIABILITY_UNBOUNDED`。
4. 有效的认证、权限、接口、容量及预算错误仍须显示。型号可选不代表服务可用或写作质量合格。
5. Qwen 不以作者显式选择 `medium` 为使用条件。R3 的固定参数仍只约束 R3。

### S07.M02 — 拉取、选模与资料来源

1. 使用作者填写的 URL 和 API key 拉取型号。无需先选择厂商预设，也无需逐个登记新型号。
2. 预设选模、端点列表选模及手填确认共用解析。匹配依据为实际端点、协议和型号，不能仅看厂商显示名称。
3. 保留接口返回且含义明确的容量及能力字段。列表只有名称时，不据此推断容量或思考档位。
4. 同一字段优先保留作者手动值。自动资料优先用接口明确信息，再用匹配实际服务的可靠资料。
5. 设置页区分“接口取得、资料匹配、手动设置、未识别”。未知值允许填写，不阻断标准调用。
6. 仅刷新列表不改已保存配置。切换型号、端点或协议后，不沿用旧服务的自动能力或专用参数。
7. 作者设置的输出限制可以保留。它仍是作者限制，不能改标为新模型能力。
8. 选模后的设置须进入保存、重开及实际请求路径。主进程不能再次要求命中旧型号名单。
9. 结构化输出等单项能力独立解析。已核实支持 JSON 模式时，容量等资料不完整不能使该能力丢失。
10. 结构化任务按实际服务、协议和型号使用已核实的格式参数；不得向其他端点套用。
    未知服务仍可标准调用，不猜测 JSON 支持，也不因缺少该能力拒绝调用。

线程 10 的 `32957562` 修补了硅基流动已核实 JSON 能力未进入请求的路径。
单项 JSON 能力不代表容量、用量或全部功能均已验证，也不保证报告字段与事实正确。
报告接收及错误归因按 [S06C 现行补充](S06C.md#review-output-reception)执行。

### S07.M03 — 容量、输出与预算分别处理

1. 区分输入容量、总上下文容量、单次输出限制和思考预算。只按供应商已定义的字段含义使用资料。
2. 不把含义不明的 `max_tokens` 当总容量。输入上限也不能自动当作含输出的总上限。服务分别限制思考和最终回答时，分别发送对应限制；不能用最终回答上限冒充思考上限。
3. 自动补齐已知能力，并据此求实际可用输出。新根按下方共同容量规则处理，不再由目标字数或语义估算设置较低物理上限。
4. 保留作者较低的限制和后续手动修改。手动值超过已知能力时须说明实际限制。
5. 未知能力保持未知，按运行设置和应用限制规划。用户值和运行估算不能标为已验证的供应商上限。
6. 不得为容纳请求而静默删除作者必需材料。真实容量不足时沿用范围调整或明确失败路径。
7. C01 的预算记录区分运行估算与已验证硬上限。分别受限且都会计费的思考与最终回答，须共同进入请求预留。复用现有 `canBoundTotalLiability`，不增加第二套账本。
8. 可信实际用量完整记账，不能截平。实际超过估算不自动视为硬上限违约。用量字段是否包含思考，与请求上限是否包含思考分别判断；结算不得重复累加已包含的思考用量。
9. 根预算耗尽时停止后续请求。已验证硬上限违约仍按原规则处理。
10. 缺失或不可信用量保留估算与未知标记。估算配置不承诺供应商费用硬上限。
11. 正常步骤和有限恢复共用原根预算。结果未知不自动重发，也不能换 root 清空旧用量。
12. 用量未知与正文未完成分别判断。空正文或缺少完成证据，不能保存为成功。

#### S07.M03 现行合同：共同容量与冻结根责任（2026-10-04）

本节统一取代同日旧增量中的规划专用容量、固定 parts 成本及 `L = 65536 × R`。
新 root 使用 `s07-capacity-v2`，适用于独立规划、正文、审稿、修稿及 Agent；真正已存 root 和 child 保持原政策。
内容与单次动作范围见 [S06A](S06A.md#chapter-planning-recovery)，普通及 Agent 接线见 [S02](S02.md#planning-controls)、[S06D](S06D.md#agent-planning-scope)。
正文篇幅按 [S06B 现行规则](S06B.md#prose-length-overrun)。本节不改变审修次数、正式文学配置及批次通过线，也不证明实现或验收完成。

**实际输出容量**

新建和重置模型配置的共同输出默认以 65536 起步，已验证的 provider 上限更低时取小值。
已有作者显式配置保留。界面显示实际有效值，不能显示 model.maxTokens，却由隐藏的旧 capabilities.maxOutputTokens 另行缩限。

先求有限用户输出值与已验证服务上限下的可用输出，再按完整输入、context、思考责任、安全余量及根剩余共同准入。
服务能力未知时仍沿用 M01 的通用兼容规则；用户值和应用估算不能改标为已验证能力。
在语义估算拒绝前完成实际容量计算。估算可帮助蓝图缩批，至少一项能否发送取决于真实物理条件。
规划目标字数不再折算输出上限或最低输出准入门，不另设新规划 8K/4K 限制。
保留有实际旧消费者的 legacy fallback，不能为清空数字搜索结果而删除。

移除 directory compact 独立的 32,768 UTF-8 字节拒绝，必要材料由共同实际容量准入。
保留 1024 消息和 8 MiB 整体可见结果资源边界，以及项目隔离、来源、lease、CAS 和取消保护。
这些字节边界不能用于证明完整任务输入、模型思考或账单上界。
`max_tokens` 仍须表达有限输出；省略参数不代表无限。
不新增通用独立思考 token 参数，不把推理强度换算成固定 token 数；已有明确字段按 M03/M04 使用。

**有限次数与累计责任**

架构在首步 begin 前冻结完整意图与范围。N 为选中的大纲章数，未选大纲时为 0。
P 沿用选中前置步骤的既有成本，不维护第二份常量表。

| 前置步骤 | P 的贡献 | 既有上界依据 |
| --- | ---: | --- |
| premise | 1 | 一次初始生成。 |
| characters | 17 | manifest、既有角色分批恢复及一次 syntax repair。此成本不是蓝图角色数组的数量限制。 |
| worldbuilding | 2 | 初始生成和一次既有 continuation。 |

架构请求上界为 `R = max(32, P + 2N)`；每章 normal 与 compact 各最多一次。
目录使用共同 `planBlueprintGenerationCost.recoveryCallBound`，上界为 `R = max(32, 3N - ceil(N/5) + 1)`。
目录 N 来自冻结的 requested-range，不能按剩余章数重置额度。物理批次最多 5 章，新动作最多 10 章。
新 Agent root 仍为有限 32 次，child 共用父根。其他工作流沿用既有请求次数，不因本节增加重试。
32 是既有最低次数，不能再额外加 32。

新根累计 token 责任为 `L = R × B`。B 与实际 reserve 使用同一个协议责任计算，覆盖冻结模型下允许的单请求 tokenLiability。
输入、输出、独立思考或已验证 total bound 按各自协议计入。窗口已含输出时不重复计，能力支持下限不能当责任上限。
未知 context 的兼容分支保留原 2,097,152 单请求准入责任界限，并在该 B 内同源地求可用输出。
这是应用估算额度，不是供应商真实思考或计费上界；usagePolicy 仍为 unknown，canBoundTotalLiability 仍为 false。
旧根首请求原本不能承受超过该值的输入责任，此兼容边界不比旧首请求更紧。
不能因此封禁全部未知模型，也不能由输入或结果字节上限伪造思考上界。
已知 context 和 total-bound 继续使用各自协议，不受该 fallback 缩限。

每次真实发送才 reserve，可信实际用量释放差额，UNKNOWN 保留原责任。
L 表示授权责任容量，不表示预计或实际消费。完整记账及已验证硬边界仍按 M03。
根活跃时间沿用有限 `T = 112500 ms × R`，不新增计时系统。
无效整数或乘法溢出在 begin 前拒绝，不通过缩短作者范围修正。
R 不是自动重试授权；实际容量、时间或根剩余不足时仍可停止，须保留成果和实际原因。

**冻结与恢复**

主进程校验动作意图、范围、内容协议及预算后绑定来源。子步骤不能提额。
child 的内容 scope 与父根预算分开冻结。旧父根新建 child 可使用新整章 scope，仍遵守父根原额度。
已存 root、child、费用和历史失败不追溯变更；恢复不能按最新常量重建旧预算。
未知版本不盲信，完成 UNKNOWN 不自动重发；完整 STOP 仅用量 UNKNOWN 时可按内容合同采用。

**可观察验收**

- 通过实际 owner/SQLite 与最终请求验证普通入口和 Agent 的共同有效输出，包括低用户值、65536、低 provider 上限及完整输入不足。
- 验证新建/重置默认、已有显式值保留、设置重开，以及 model.maxTokens 与 capabilities.maxOutputTokens 的实际一致性。
- 核冻结 root 的 B 与 reserve 同源；未知责任累计不提前撞旧固定 L，可信 usage 释放差额，未知 context 不冒充可证明费用上界。
- 检查已知 context/total-bound 未误用未知分支上限，独立思考及窗口内输出不漏算或重复计。
- 核默认 5/600、可选 10/1000 及 11 章/1001 目标拒绝的实际登记；目标超限与完整输出超目标须分开。
- 核首步冻结、同根 child、旧 root/child 恢复、重复批准、取消、未知完成和晚到结果，不只验证成本公式。
- 43,699 字节 compact 材料在容量足够时可派发；真正完整 prompt 超限时零派发，必要原文不被静默截除。
- 原 10/50/200 章耐久与性能证据保留在历史冻结根或聚合层，不缩成 5 或 10 冒充原范围通过，不付费生成 200 章。

真实检查只按[现行规划工作包](../../../research/novel-quality-modernization/thread10-delivery-plan.md#planning-completion-work-package)执行，不新增文学通过率门。

### S07.M04 — 统一思考档位与实际参数

1. 软件档位为 `off/low/medium/high/xhigh/max`，保留 `auto` 和旧设置兼容。
2. 复用 `reasoning-policy`、`providerValues` 及现有请求转换层。按实际服务和模型系列转换参数。
3. 映射可以转换字段名称及字符串、数字或开关值。未知型号不得因缺少映射而被禁用。
4. 只采用有依据的映射。用户示例 `xhigh → Extra` 不是可直接加入的厂商规则。
5. 没有可靠映射时省略专用参数，使用服务默认。不得猜参数或付费逐档试错。
6. 只支持开关时显示“仅支持思考开关”。不能把全部强度档位标成已生效。
7. 服务缺少某档时采用可解释的映射，并显示实际结果。不同模型的同名档位不承诺等强。
8. 显式关闭不能被转换为开启。服务无法关闭时须说明限制，不能显示“已关闭”。
9. 设置预览显示请求档位和实际发送参数。省略参数时显示“服务默认”；保留最小手动修正入口。
10. 参数须到达共同请求出口。分别说明界面选择、实际发送和服务端支持依据；发送成功不证明服务端采用了该档位。模型原厂支持某字段，也不证明转售服务提供相同支持。
11. 服务使用数值思考预算时，可复用现有数字映射。应用选择的预算须标为应用映射，不能宣称是厂商对同名档位的定义。保留手动值及显式关闭，不向其他端点或未知型号套用专用参数。
12. 容量上限和应用档位不能代替任务所需的思考额度。普通审稿的配置须同时检查实际耗时、完整报告和漏检/误报；思考更多不等于质量更好。降低思考开销时保留作者材料及最终回答空间，不用压低最终回答上限替代思考预算。

参数依据以实际服务为准。
硅基流动的 [API 文档](https://docs.siliconflow.cn/docs/api/chat-completions-post)和[思考模型说明](https://docs.siliconflow.cn/docs/userguide/capabilities/reasoning)将最终回答长度与思考预算分开。
截至 2026-10-03，文档说明 Qwen3 系列支持 `thinking_budget`；具体型号的实际兼容仍须验证。
其 `reasoning_effort` 适用清单未列出 Qwen，不能据已发送 `medium` 宣称该档生效，也不能仅据未列出就断言服务忽略了它。
本段只说明映射依据，不新增型号准入名单或长期成功保证。

### S07.M05 — 运行中断、等待与恢复的透明诊断

1. 共同请求入口保留失败阶段、允许记录的错误类型及底层原因代码、HTTP 状态和同钟响应时间。实际运行环境写入验证记录；不保存凭据、原始错误全文或思考正文。
2. 连接响应与有效输出分别记录。思考属于有效输出，连接心跳不冒充正文或审稿报告。未采集的阶段时间保持未知，不能按 Token 比例倒推耗时。
3. 等待界面显示已等待时间、最近响应和报告是否完整。没有新响应不能继续暗示模型正在输出，也不据此自动取消有合法执行预算的请求。
4. 网络异常、调用方取消、根预算终止和程序进程被外部停止分别说明。仅凭异常名称不能认定作者主动取消；调用方信号还须结合已有原因区分用户操作与系统预算。
5. 未取得完成证据时不保存空报告，不修改原稿；实际用量未知按原规则保留。重新审稿若会发新请求须明示，已保存结果直接打开不重新调用模型。
6. 错误记录、提示及恢复行为修复，不证明原中断原因已修复。真实调用正常结束只证明该次运行；根因结论须绑定实际错误证据、针对性修复及对应验证。
7. 单元测试、受控断流、实际桌面连接真实服务、文学结果分别报告。不同 Node/Electron 运行环境的结果不能合并为同一环境的可靠率；主动停止与 NOT_RUN 不计作自然网络失败。
8. 恢复验收须覆盖实际 V3“重新审稿”入口：保留失败前原稿、已保存报告和编辑状态；按现有终态/对账规则显式重审，取得完整报告并可保存、重开。旧 UNKNOWN 及用量记录不清除。只改善提示、通过受控断流或跑通纯 Node 调用，均不能代证真实桌面恢复。

本节描述现有诊断与恢复路径，不授权新增监控平台、自动重试或无限延长超时。
当前修复顺序、诊断配置和真实调用范围由线程 10 交付计划规定。

在现有测试和审查中引用以下编号，不另建验收平台。

| 编号 | 代表性场景 | 必须观察到的结果 |
