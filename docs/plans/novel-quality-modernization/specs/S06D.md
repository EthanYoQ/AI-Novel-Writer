## 现行增量：Agent 规划范围与父根预算分离（2026-10-04）

本节与 [S06A](S06A.md#chapter-planning-recovery)、[S07](S07.md#planning-budget-range)共同规定新规划行为，不证明实现或验收完成。
Agent 仍调用现有工作流，child 共用父 rootActionId、已用次数及未知责任，不另开 root 绕过预算。

- start_workflow 的架构、大纲和蓝图动作携带实际章范围与目标，在 ConfirmCard 前归一化。
  主进程复核作者批准的同一组参数，不能在确认后静默恢复全书范围。
- 每次规划默认 5 章，可选 1–10 章；每章目标默认 600，可设为 1–1000。完整输出的接受规则与普通入口相同。
- child 单独冻结整章 planning scope 和目标，父根冻结预算。内容协议不能仅因父根使用旧预算版本而回退到旧全书行为。
- 已存 root 和已存 child 保持各自原政策、协议及费用。旧父根新建 child 可使用新内容 scope，但额度仍由旧父根限制。
- 新 Agent root 沿用有限 32 次，共同输出容量按 S07；批准执行不暗中增加父根额度或清除 UNKNOWN。
- 目标进入真实 system 消息；偏好、确认、恢复、编辑保存和缺章继续复用 S02/S06A，不新增 Agent 私有设置或恢复账本。

验收经过实际 owner/SQLite、普通入口及 Agent ConfirmCard。
核对默认 5/600、可选 10/1000、范围与目标越界拒绝、实际有效输出和 system 目标一致。
核对同根计账、旧父根下新 child 的内容范围、已存 child 恢复、重复批准幂等和旧费用保留。
单元测试只检查工具参数或模拟 root，不足以证明主进程接线完成。
