## 现行增量：逐章大纲与完整范围恢复（2026-10-04）

本节定义新规划动作的前向合同，不证明实现或验收完成。
预算由 [S07.M03 规划增量](S07.md#planning-budget-range)独占，实施和真实验证顺序见[线程 10 规划工作包](../../../research/novel-quality-modernization/thread10-delivery-plan.md#planning-completion-work-package)。
以下要求取代原文中冲突的新建大纲行为；原冻结规格和旧运行记录保留。

### 动作与候选采用

1. 完整架构在第一步生成前冻结 `ArchitecturePlanningIntent`，包含选中的前置步骤和大纲章范围。
   独立步骤冻结自身意图。主进程将同一政策用于来源绑定和 root，后续步骤不得改范围或提额。
2. 新 `chapter-markdown-v1` 大纲协议每次只请求一章普通 Markdown，具有唯一明确的章标题。
   新候选拒绝章组标题、额外章节和章外内容；旧作者章组按 [S10A](S10A.md#planning-chapter-selection)保留。
3. 单章正文目标约 600 Unicode 字符，完整条目含标题的接收上限为 1200 Unicode code points。
   这两个数是本次内容合同，不是 token 限制，也不是已证明最优的文学长度。
4. 每章 normal 最多一次。出现 LENGTH、无效结构或超长后，最多从冻结作者事实及已接受前缀紧凑重建一次 compact。
   不先续写补齐失败长稿，不把失败候选中的临时情节当作作者事实。
   重建须保留作者硬目标、身份、数量、时序、禁令、尾部要求及已接受章节。
5. compact 仍无效、超长或 LENGTH 时停止，保留失败 artifact、诊断和已接受候选前缀。
   不截尾通过长度检查，不覆盖旧正式大纲，也不自动开始下一轮压缩。
6. 主进程验证原始 artifact 后才按章序加入 composition，以双换行连接完整章条目。
   不使用续写重叠裁剪删除章标题或正文。新协议最多接受冻结范围内 N 个章 artifact，旧协议的 32 个限制不变。
7. 全部选中章节完整通过后，才按原 `sourceExpected` 执行一次正式 synopsis CAS。
   CAS 比较生成开始时的来源后再保存。追加保留已确认前缀，重写不能丢弃已确认尾部，冲突保留候选。

### 恢复与既有蓝图

主进程从持久 attempt、artifact 和 composition 派生 request、accept、complete、stopped 状态。
稳定 purpose 为 `plot-outline:chapter:<n>:normal|compact`。发前检查下一章与合法尝试。
换 nonce、并发或重启不得增加 compact 次数；有效 artifact 已保存但未采用时，恢复直接验证采用，不重发模型。
导航检查点由该状态重建，零输出或短输出不能因旧长度门槛而丢失恢复入口。

已派发但完成结果无法确认时，停止自动推进，不盲重发。
完整 STOP 文本仅用量未知时，可按内容合同采用文本，但保留未知用量责任。
旧 `s07-task-and-liability-v1` 和已存 `legacy-range-v1` root 继续各自政策与恢复协议，不套用新逐章合同。

最终提交丢回包时，在现有提交路径内只读核对数据库。
数据库仍等于初始来源时执行原 CAS；数据库精确等于已验证完整目标且其他来源未变时返回已是目标。
第三种文本或其他来源变化仍冲突，不推断历史提交者，不改旧收据。

蓝图继续复用既有每批最多五章、单章一次 compact、结构验证及完整前缀保存。
本增量调整其新 root 的输出及范围预算，不重写蓝图 executor，也不新增默认压缩调用或摘要数据库。
旧作者资料不得后台压缩覆盖。

### 可观察验收

- 以 10、50、200 章的确定性范围与恢复检查验证无缺章、重复采用或预算重置，不付费生成长篇验证计数。
- 覆盖 1200 与 1201 code points、截断、额外章节、章组、尾部硬事实和 compact 再失败。未接受内容不得进入正式 synopsis。
- 覆盖第 33 章及更大合法范围、已保存 artifact 的恢复、并发重复申请、UNKNOWN、源编辑冲突和提交丢回包。
- 全范围失败后旧正式大纲不变，候选可读；全范围成功后真实保存及重开结果一致。

## 实施步骤

1. 逐项对接 root action 与冻结输入，将 renderer 自有 attempt/终态/失败保存改为主 owner 收据。
2. 大纲按用户范围/成功覆盖键生成与恢复；只提交完整验证项，JSON 残片保留可见候选。已有世界观候选和压缩上下文修复先复验再复用，不能重做。
3. length/取消/网络失败返回原因与持久候选，不把未完过程当成功；恢复不重写已完成章节范围。
4. 保留当前角色写入批准边界直到 S09A 接力，标记未迁身份消费者，不能提前宣传角色问题已修。
