## 现行合同：整章规划、软目标与作者恢复（2026-10-04）

本节统一替代同日旧增量中的 1200 字拒收、固定三／五部分兜底及新动作全书范围。
原冻结规格、历史失败与已存运行保留原解释。本节是实施要求，不证明实现或验收完成。
界面接线见 [S02](S02.md#planning-controls)，Agent 同根规则见 [S06D](S06D.md#agent-planning-scope)。
共同容量和预算只读 [S07.M03](S07.md#planning-budget-range)，实施顺序见[规划工作包](../../../research/novel-quality-modernization/thread10-delivery-plan.md#planning-completion-work-package)。

### 动作与冻结输入

1. 每次大纲或蓝图动作默认 5 章，可选 1–10 章。普通界面、Agent 确认和主进程登记使用相同边界。
   项目总章数可大于 10；超出单次范围时在开始前要求缩小选区，不自动遍历全书或新增全书队列。
2. 大纲与蓝图的每章目标各默认 600，可设置为 1–1000 的整数。
   目标仅指导大纲正文或蓝图 keyEvents 的主叙述，不包含 JSON 字段名及身份、关系元数据。
   中文按汉字量、其他写作语言按既有词数单位表达；使用 WritingLanguage，不随界面语言改变。
3. 本机偏好为 GlobalConfig 的 `outlineTargetUnits`、`blueprintTargetUnits`，缺省均为 600。
   在既有 GenerationAuthorInput 中冻结单一 `planning:target-units`，同时冻结架构意图和实际章范围。
   normal、compact、重开均读取冻结值。改偏好只影响下一个经确认的新动作，不新建项目设置或迁移服务。
4. 目标写入真正的 system 消息，保留既有 Skill 注入。
   BasePromptBuilder.systemSuffix 的 user 内容不满足此要求。
5. 1000 是目标设置上限，不是结果上限。结构完整且完成可信时，低于或超过目标均保留原文。
   不新增 ±30% 长度校验、截断、强制压缩或拒收。正文保存和文学验收的 ±30% 不受本节影响。

### 整章采用与有限恢复

大纲使用 `chapter-outline-v3`，一次物理请求只生成一章，章标题唯一明确。
新候选拒绝额外章节、章组标题和章外内容；旧作者章组按 [S10A](S10A.md#planning-chapter-selection)保留。
每章 normal 最多一次。仅已知结构无效或真实 LENGTH 时，从冻结作者事实及已接受前缀重建一次 compact。
完整 STOP 超过目标不触发 compact。重建保留身份、数量、时序、禁令、尾部硬要求及已接受章节。
失败候选不是作者事实；文本看似闭合不能将 LENGTH 改判为 STOP。

蓝图沿用现有有限分批、拆批及单章 compact，每次物理请求最多 5 章，可按容量缩小批次。
动作最多 10 章与一次请求最多 5 章是不同边界，不新增蓝图 executor。
取消 title、role、purpose、keyEvents、suspenseHook、角色姓名（含新角色候选）和关系描述的人类文本长度拒绝。
取消 characters 超过 12、relationships 超过 8、newCharacterCandidates 超过 12 的数量拒绝。
保留必要类型、非空、唯一身份、合法角色引用、精确范围覆盖、关系端点闭包及整体资源检查。
不换成其他任意数量限制，也不在首个长度错误后跳过其他验证。

删除固定三／五 parts 的请求 purpose、提示词、解析、装配、completeParts/missingParts、专用成本及仅服务 parts 的测试。
保留整章 artifact、cursor、原来源快照、确认前缀、原子准入、CAS 和收据；已关闭的 Map 读取及窄 SQL 性能修复保留。
私有未发布 parts 根只作不可误重放的历史证据，不为它们新增迁移器。真正已存 root、child 仍按各自冻结协议读取和恢复。

主进程从持久 attempt、artifact 和 composition 派生状态。
大纲 purpose 沿用 `plot-outline:chapter:<n>:normal|compact`；并发、换 nonce 或重开不能增加尝试机会。
有效 artifact 已保存但未采用时，先验证再采用，不重新请求模型。
完整章按顺序以双换行组合，不用续写裁剪删除标题或原文。

### 保存与作者恢复

全部选中章节完整通过后，自动路径才按原 sourceExpected 执行正式 synopsis CAS。
保留已确认前缀及范围外原文，冲突时保留候选；不以部分成功覆盖整个旧大纲。
提交回包丢失时，复用现有路径核对数据库。仍等于初始来源时执行原 CAS。
数据库精确等于已验证目标且其他来源未变时返回已是目标；第三种文本或其他来源变化仍报冲突。

第二次仍截断或结构无效时，不继续自动付费重试。预算不足或完成 UNKNOWN 时也保留候选原文和完整章。
错误入口须打开实际可编辑工作稿，标明完整章与缺章，不能只展示提示或只读 artifact。
作者可零模型保存完整连续前缀。明确作者保存与自动全范围保存分别核验，范围外原文不变。
保存后只继续缺章；零完整前缀也须有明确的新动作入口，不能要求编造一章或空 synopsis。

继续前，本地请求须已结束，主进程须持久撤销旧 run 的采用、保存、resume、rebind 权。
复用既有生命周期；如不足，只扩展规划专用私有 run effect，不新增通用 metadata 或表。
既有 binding_json 六字段及 fingerprint 不变。本地停止不能冒充远端取消。
主进程核验缺章范围，预填原目标并经作者再次确认后冻结。来源冲突走现有出口，丢回包后的重复确认须幂等。

完成 UNKNOWN 不自动采用或重发。完整 STOP 仅 usage UNKNOWN 时可按结构采用，未知责任仍保留。
旧 FAIL、UNKNOWN、费用和历史收据不改写；作者继续不追溯提高旧根预算。
内容 scope 与预算分开冻结，Agent 下新 child 的边界按 S06D 执行。

### 可观察验收

- 以实际 owner/SQLite 验证 1、5、10 章及 600、1000 目标；11 章、1001 目标在登记前拒绝。检查普通入口和 Agent 一致。
- 检查冻结目标实际进入 system；改偏好后旧动作 normal、compact、重开仍使用原目标。
- 完整输出超过 1000 或偏离目标 ±30% 仍可完整读回。蓝图 13 角色、9 关系及超过 12 候选可采用；重复身份和无效端点仍拒绝。
- 超过旧 32 字符的角色姓名、超过旧 80 字符的关系描述仍保留全文。保存及重开后，角色、候选和关系端点身份一致，尾部事实完整。
- double LENGTH 不产生 parts 请求；覆盖实际编辑、零模型保存、零前缀继续、在途请求、晚到写入、来源冲突和确认丢回包。
- 覆盖 artifact 保存后恢复、并发、取消、UNKNOWN、全范围自动保存及 portable 历史，不能仅检查函数返回值。
- 原 10/50/200 章耐久与性能证据保留于旧冻结根或实际聚合层。不得把 200 改成 5 或 10 后称原用例通过，也不付费生成 200 章。
- 默认值与可选上限是用户决定，不是已测出的稳定极限。真实检查沿用[六章大纲、六章蓝图和一章正文旅程](../../../research/novel-quality-modernization/thread10-delivery-plan.md#planning-completion-work-package)，不另设文学门。

世界观、架构、角色规划、大纲和单字段等入口都经过统一运行边界；本片不改角色事实 schema、不另设阶段硬帽。 DSH、真实小说和正式发布不在本片。

## 文件所有权

`src/services/workflows/commands/{architecture,directory,planning-material,generate-field,analyze-style}.command.ts` 及其专属 helper/tests；角色生成阶段在当前 architecture 实现内按 S00 消费者表覆盖。不改正文/batch/Agent store 或核心 ledger。

## 实施步骤

1. 逐项对接 root action 与冻结输入，将 renderer 自有 attempt/终态/失败保存改为主 owner 收据。
2. 大纲按用户范围/成功覆盖键生成与恢复；只提交完整验证项，JSON 残片保留可见候选。已有世界观候选和压缩上下文修复先复验再复用，不能重做。
3. length/取消/网络失败返回原因与持久候选，不把未完过程当成功；恢复不重写已完成章节范围。
4. 保留当前角色写入批准边界直到 S09A 接力，标记未迁身份消费者，不能提前宣传角色问题已修。
