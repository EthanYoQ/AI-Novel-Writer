# S10B — 写稿、审稿、修稿共享章节证据

<a id="planning-required-material-consumption"></a>

## 现行追加：长规划进入真实正文请求（2026-10-04）

按 [S10A 必需原文合同](S10A.md#planning-required-material-capacity)接通 draft 准备入口，复用 review/revision 的 receipt 安全上限。
写稿、审稿和修稿使用一致冻结来源、准备绑定和准入语义；来源替换仍须拒绝，不能临发送时补读未绑定资料。
draft 的材料选择探针与最终选择须使用同一规则，不能先按已纳入历史删除参考，再在最终选择中省略该历史。
确定性检查须经过真实 draft 准备及主进程容量准入，生成响应可控且零网络。
必需材料超过原 8000 字等值目标但实际容量足够时请求可达，尾部时点与全局约束须逐字存在于实际 prompt。
可选材料按总纳入量保持原预算及省略记录。加入短细纲后实际超限时零正文请求，并保留原文、来源及明确原因。
本章 keyEvents 的末尾强化继续计入容量。须核 writer/review/revision 来源回执一致及旧 run 恢复。
上述检查不证明模型遵守质量。沿用[六章大纲、六章蓝图及一章正文旅程](../../../research/novel-quality-modernization/thread10-delivery-plan.md#planning-completion-work-package)，大纲和蓝图各按 5+1 动作完成，不减少验收内容或新增文学门。

## 现行增量：消费已保存的单章规划（2026-10-04）

本节应用 [S10A 单章投影](S10A.md#planning-chapter-selection)，不证明实现或验收完成。
新大纲的采用与恢复归 [S06A](S06A.md#chapter-planning-recovery)，预算归 [S07.M03](S07.md#planning-budget-range)。

正文使用实际保存的大纲和蓝图，保留其来源及本章目标，不能换成内存示例或重新生成的摘要。
规划目标是软要求。完整输出超过 1000 字仍按来源和实际容量消费，不能变成下游长度拒绝。
必要原文、可选预算及省略记录继续按 S10A，正文保存和最终篇幅要求按 [S06B 现行规则](S06B.md#prose-length-overrun)。
明确单章边界只改变可可靠选择的大纲片段，不后台改写旧作者事实、旧章组或手工长蓝图。
本章目标在提示末尾的强化继续保留；不得以去重为由删除该合同。
写稿、审稿和修稿保持相同事实优先级，规划及短细纲仍不能作为已发生事件的证据。

定向检查核对当前章、全局硬目标、未来边界及尾部明确要求实际进入对应消费者。
同时核旧章组回退、必需材料超容量的明确失败，以及保存重开后的来源一致性。
真实范围及配置只读[线程 10 规划工作包](../../../research/novel-quality-modernization/thread10-delivery-plan.md#planning-completion-work-package)，本节不另设文学门或重复旅程。

## 目标与非目标

完整保存作者设定，但只把本章相关且有来源的证据编入请求，平衡输入爆炸与信息丢失。 DSH、真实小说改写与正式发布不在本片。

## 实施步骤

1. 接入 S10A，写/审/修共享SourceRef/候选准入/事实优先级；任务特有输出目标可以不同，证据真伪语义不能各写一套。
2. 原世界观/蓝图完整保存在事实源，ContextSnapshot仅投影；禁止通过生成阶段固定小帽来替代写作阶段输入选择。
3. receipt记录source哈希/include/omit/必需覆盖与容量裁决，公共日志不放正文；恢复fingerprint绑定该snapshot。
4. 执行第二个中文 early gate：长设定、本章事件、人物知情/物品、前章待审衔接对照。任何指定事实错/遗漏必需事件均stop，不拿更顺文风抵消。
5. 本片直接负责 `early-context`：消费S00可运行baseline/runner/protocol，提供本片已集成candidate execution manifest及双targets。先零模型验证目标代码/产物/driver身份不同、生产入口可达、根隔离和旧新fixture语义parity，再同时间窗两臂；单臂、同目标、S00旧输出或缺baseline/parity/arm-target receipt不能过门，所有调用计入80次总帽。
