## 实施步骤

1. 消费完整 S00 disposition 与 S01 journal/locator；readonly probe 不写 manifest/不改租约。SQLite backup 处理 WAL，staging 经 M00 及同 registry 到目标版本，验证 integrity/foreign keys/领域数量/原文 hash。
2. canonical chunks/documents 逐条保全（源文件已删仍可全文检索）；vectors/代际/registry 分别处理，半旧迁移不猜拼，无自动 embedding 调用。
3. 执行 prepared→verified→legacy-isolated→target-installed→switched，验证后关闭源目标 SQLite/LanceDB/枚举句柄。每一步命名/flush API、平台回执和重启物理判据记录；不能把普通 rename 说成全目录事务。
4. 原 `.vela` 隔离后旧发现路径不存在，无 alias；未知项留备份，reparse 不跟随。新库写后只 forward fix/新 ID 独立副本，原地恢复拒绝。旧二进制正式验收 S14C，本片先实现其可测试接口。
5. 本片同时拥有拟新增 `scripts/project-migration-acceptance.mjs`，复用既有 smoke/本片故障 fixture（不造第二框架），提供 help/dry-run 与独立数据根断言。所有 tracked 验收适配最迟在 S14A 冻结前合入；S14C 仅运行，不能临时改脚本后沿用旧 SHA。
