# Program v3：以真实功能与写作质量完成整合

## 1. 目标

让作者少丢稿、少重复劳动，角色与情节保持一致；在新的写手界面完成全部工作，不学习两个界面来绕过缺口。Vela退出、安全迁移、输出预算/恢复、章节上下文、角色、审修闭环仍沿用受审内核计划。

纳入：24片原内核规格、全部当前Issue的实质处置、贡献者已实现新功能及其缺陷修复、经典兼容/写手默认、角色随定稿自动更新派生信息、可行的手动云存档增强、桌面资格与授权后的发布/关单。DSH、英文产品场景、任意HTML/插件皮肤平台、通用Agent平台、实时多设备协同/云端模型托管排除。

这次交付是可开发的总计划/Spec，不是生产实施。Sol/high切片开发由后续实施阶段执行；主线程集成、完整测试、独立审查和远端操作。所有未跑检查标 NOT RUN。

## 3. 实施顺序

1. **W0 定义事实与验收**：S00复核最新工作区/远端/可执行基线、donor差异与许可、每个Issue及功能并集；S01固定单一共享owner、迁移序列、预算与派生来源合同。G01建立原Issue症状台账和复现/增强责任，只准备有证据关单建议，不靠迁移追踪降低数量。F01固定外观偏好兼容。
2. **W1 API与迁移**：S02→S03→S04；F02可在S02/F01后平行移植纯外壳/样式。S04提前登记donor头像/缓存/偏好；恢复、导入、备份后续共用同一安全迁移接缝。
3. **W2 写作内核**：S05→S06A/B/C/D→S07；S08→S09A/B/C在独占文件下并行接角色身份和自动派生更新；S10A/B→S11→S12。三个早期中文门保留，尽早发现预算/质量退化。
4. **W3 完整功能接入**：F03完成头像M05；B01据此做完整项目归档/新副本恢复，B02做手动WebDAV传输；F04在这些接缝稳定后按检查点接Writer全部旧能力/新增功能/增强，修项目切换丢稿、速览只读/授权、进度误报、保存反馈、编辑/图谱等缺陷。B01/B02只拥有服务/客户端契约，最终UI由F04统一接线。
5. **W4 默认资格**：F05逐项Writer并集Preflight+Classic兼容；主集成者激活Writer发布默认；同postUiIntegrationSha完成Final与原S07/S10B/S11三道post-UI双臂复验，仍用原80总帽。所有新功能代码在此之前完成；不能靠Classic补缺。
6. **W5 清理与冻结**：S13消费F05新receipt，退出全部生产Vela/已证实无消费者残留。S14A收口版本、工具、集成/独立review，再冻结subjectSha。S13如改变相关行为，回相应门复验；不自动继承旧PASS。
7. **W6 质量、升级、发布资格**：S14B中文18章双臂；S14C旧版升级/头像/归档恢复；同subjectSha独立数据根。S14D验证Windows x64/macOS arm64/x64真实安装与云端产物。
8. **W7 授权后对外完成**：R01精确发布已验证产物并双语说明；G02按原Issue全部范围、公开Release、近期反例核对关闭。未解决/未验证/未发布逐项保留，不报“全部完成”。

主线程每次最多派两个不抢文件的开发者；schema/IPC/main/App/构建为一个owner。F04按顺序子检查点交接，不再同时创建与其抢文件的前端worker。发现新根因回原内核owner最小修复，避免在皮肤层再写一套控制系统。

## 4. 平衡与完成定义

- 世界观完整产物与章节上下文分离；不靠压低生成上限替代上下文筛选，不以解除所有预算为解法。
- 自动派生角色状态减少人工操作，同时保留出处/时点，不把生成猜测写成作者设定。
- WebDAV只解决用户自选位置保存和恢复项目；不把远端不稳定拖进写作事务，不后台自动上传。
- 新功能缺陷需要修复；未知原因先最小复现。开发修复的范围是当前被保留功能，不做无关全量框架重写。
- 交付分别报告：逐行审查覆盖、代码修复、Writer逐功能/中文写作产品验收、三平台发布资格、已发布与Issue状态。任何必需Writer功能缺失或质量门未过，整体未完成，不能退而只发布Classic却宣称此计划交付。
