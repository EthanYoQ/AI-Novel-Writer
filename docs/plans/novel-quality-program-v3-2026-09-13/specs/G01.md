# G01 — Issue实际修复/增强台账与复核

依赖S00、S01。独占脱敏Issue症状/验收表、公开说明草稿与回执；不改生产代码，worker不直接远端写入。目标是明确问题并交付，不是少几个open。

1. fresh-read全部开放Issue（排PR）、正文/实质评论/关联PR/检查/Release，快照10项只作起点。区分用户报告、当前复现、代码合并、发布。
2. 每个原症状映射一个验收owner、具体代码片/失败反例/完成证据。#187所有流程、#191两半、#221两症状、#213完整跨设备云存档不可遗漏；使用03矩阵。
3. #199/#205是已发布证据复核候选，有缺口/新反例则继续修复，不重复已完成实现；#211即使已merge仍按v3产品/发布门，不列当前已完成。
4. 原产品Issue保持open；可建实施child但不能建successor就归档原项。PR只Refs，禁止merge自动close未发布用户问题；不套7日无回复自动关闭。#219原因未知先最小复现/参数解析追踪，不能假定主角缺失一定身份Bug。
5. #191复用现有导入/定稿provenance，C16非冲突derived自动补；#213由B01/B02/F04交付，不再长期排除。尚缺资格/真实云服务等列阻塞，不填PASS。
6. 缺信息一次说清版本/系统/model/provider原名/已支持非秘密参数/最小中文步骤/期望与脱敏诊断；可自行复现就不等待。当前没有“已请求仍未补”的符合项；即便后来无回复，本计划仍留待核实而非伪修复。
7. 主线程在执行阶段明确授权后才逐项fresh-read→说明→close→回读状态/URL；只可关闭原范围已实际完成的项，未授权交稿即可。误关透明更正/reopen，不删反馈。

验收：10项原始症状零漏项，每个验收owner唯一，状态如实；#187部分修复/#211未发布/#222开放PR/#224 CI失败不被误标完成。使用简单台账和只读gh验证，不建自动关单机器人。

交付：可关闭复核建议与证据、仍需修复/增强清单、已复现与缺信息分别列出。没有行政归档成功计数；数量不减少也不构成失败。

## 执行合同


模型：Sol/high。你不是唯一开发者，不回滚他人修改，禁止再开子代理。只改本片独占文件；共享区仅交一个接线请求给主集成者。先读本包01/04/05、旧通用执行合同及依赖Spec。源路径以开工实际工作树为准；拟新增文件必须登记。状态NOT STARTED，下面是要执行的检查，不是已通过证据。完成给出依赖/最终SHA、实际命令/退出码、证据/未执行项；密钥/作者原稿/本地路径不上传。DSH排除、产品场景仅中文。
