# B02 — 手动WebDAV云存档，不可变版本与可恢复分叉

依赖B01、S03。独占WebDAV服务、OS秘密store、CloudProjectBinding本机非密store、专用typed client/contract及网络测试。拟electron/services/{webdav-backup-service,cloud-credential-store,cloud-project-binding-store}.ts；全局main/IPC/types由主集成者接线，UI归F04。不写项目DB或自建迁移解释器，模型Sol/high。

## 最小可用范围

用户配置一个WebDAV端点后，手动备份、列出完整世代、选择恢复为新副本。B01负责全部资产/当前权威/候选冻结，B02只传输合格归档。不做实时双向同步/任意Git/自建云/provider插件/后台上传/远端自动删除。

## 实施合同

1. main独占用户端点/账号与OS-backed秘密，密文存canonical app-data，不进renderer/localStorage/项目/日志/模型。安全存储不可用仅session内存且明确提示；提供更新/清除，不明文降级。
2. HTTPS/TLS默认不绕过，不携凭据跨origin/HTTPS降HTTP跳转。仅显式loopback HTTP可作受控本地服务（127.0.0.1/[::1]/localhost且绑定loopback）；远端HTTP拒绝。DAV href规范化后必须同origin且在配置根内，拒绝编码穿越/根外路径，XML禁外部实体并限大小。标准库优先，不再造网络框架。
3. **不可变generation才是真相**：随机唯一generationId目录、archive/manifest，完整上传且校验后才写完整completion descriptor；列表只接受可验证完整世代。应用不覆盖/删除既有generation，未知结果重试先核验相同对象hash或改新ID，不能盲覆盖。半对象不显示成功。latest只作可选hint，支持安全条件写才更新，不支持就不写；列表/恢复不依赖latest，缺CAS不会让整个服务不可用。
4. 每世代记录用户实际选择的parentGenerationIds；同父的A/B都可以append，两个都保留并显示分叉/可恢复版本，不按时间戳假装已同步或唯一最新。无需构建通用版本DAG界面，仅显示“来自同一备份的两份修改，请选择恢复/另存”，不自动合并。
5. B02是canonical app-data/cloud-backup-bindings.json唯一writer（原子更新/revision）：localProjectId、cloudBookId、localEndpointAccountId、lastSelectedParentGenerationIds、mode(unconfigured/writable/origin-readonly)、revision。此本机表/本地账号引用不入归档，密码另库。上传基准取持久且用户已认可的父世代，不fresh-read latest偷偷采纳；上传后binding失败时报告本地状态未保存并保远端版本，重启可列出重新选择。
6. B01恢复副本只携cloudBookId/originGeneration的只读来源，B02目标机创建origin-readonly绑定；重启仍不自动推送。用户在目标机明确选账号、重绑旧云书并选父世代（或新建云书）才writable。清凭据把连接置unconfigured，不清历史/不自动重授权；确认删除本地项目才清其本机binding，移除最近列表/关闭项目不等于删除，不删除云版本或共用账号。
7. B01完成快照后释放源锁，网络期不锁住写作；显示备份时点/本地新改动，不冒充实时同步。网络请求/重试/超时/流式大小有界，取消/错误不丢原稿；下载交B01 staging/schema/path/hash/来源检查及新副本安装。
8. 初次配置和每次上传摘要说明目标、内容范围/大小、服务端可见、首版非E2E，手动确认才上传。明确作者正文原样上传、不承诺自动过滤作者自行写在正文里的秘密。不能探取真实小说/云账号。
9. 给F04统一action/view：connect、backup、list、restore-copy、cancel、clear-credential、confirm-binding；状态包含未配置/连接/上传/时点/分叉/本地绑定未保存/恢复完成/失败。所有归档/当前权威/运行冻结仍由B01与原owner负责。

## 必测与完成门

拟webdav-backup-service.test.ts、cloud-credential-store.test.ts、cloud-project-binding-store.test.ts、test/desktop/webdav-backup.fixture.ts，相关vitest/typecheck/native profile。mock不代替受控WebDAV真实网络和两个隔离打包profile的F04按钮闭环；仅合成小说/账号。

- A备份、B列出/下载/恢复新副本，全部资产含头像/知识、当前权威/来源映射合格，能重开继续操作，旧任务不自动执行。
- 无CAS服务可append/列/恢复；latest缺失/过期/错误指向半对象不影响完整世代发现；同父两个新世代都保留，不覆盖不假同步。
- A gen1退出→B在gen1上gen2→A重启仍以持久父gen1生成另一个child，两个branch可恢复并明确选择。恢复副本重启origin-readonly；清秘密不改变历史归属；关闭项目不丢binding。
- 部分上传/断网/凭据失效/取消/错长度hash/未知PUT结果/本地binding更新失败，原稿/已有云世代不变，状态如实；不靠last-write-wins重试。
- DAV同origin根外href、编码穿越、跨origin/降TLSredirect、外部实体、响应超大拒绝；不向根外GET/PUT或泄漏Authorization。
- OS凭据落盘仅密文/读取仅main，轮换/清除重启生效，安全存储不可用session-only；归档/诊断/renderer负样本无秘密。
- 恢复损坏/恶意路径/未知schema/目标已存在交B01拒绝，当前原件不变；源码/当前性映射仍守C17。

受控loopback只证明本协议实现，不宣称兼容所有第三方云盘。缺真实服务/打包profile/OS秘密验证记blocked/not-run；macOS秘密与网络入口由S14D对应目标实际验证。所有代码/工具在F05 post-UI及S14A前完成；#213只在完整功能公开发布后关闭，不能只合并B02就关。模型调用为0，继续创作的模型验证复用原80帽内案例。
