# R01 — 精确产物发布（显式执行门）

依赖S14D；只有代码、产品质量、升级和三个平台资格都满足，且用户明确授权当前发布动作才执行。worker仅准备公开双语说明、checksum/receipt与步骤草案；主线程负责GitHub操作。此Spec不授权本轮merge/tag/release。

输入：S14A冻结subjectSha（已含版本/默认Writer配置/所有tracked工具）、S14B/C/D同SHA receipts、实际产物hash、独立code-review结论和公开内容白名单。

1. 确认公开分支/PR当前状态、保护规则/CI、源码与证据对应。PR保持Draft直到当前code-review和产品门完成；不要自动关闭issue/合并未确认贡献PR。
2. 版本号在S14A前已固定；R01不改package/lock/源码再拿旧结果发布。发布tag必须精确绑定经测试subjectSha（或回S14A针对新的实际SHA完整重新资格），不能用“diff看起来一样”将merge SHA冒充被测SHA。
3. 获授权后按仓库政策合并/发布，保证subjectSha为已合入可追踪提交；合并策略若导致原subject无法成为合法发布目标，先停止，重新冻结/验证，不偷偷换tag对象。公开产物必须就是S14D验证的hash，不在发布时重建一个无证据的新包。
4. 发双语说明：每功能一句非技术语言；分完整写手/经典回切、头像与编辑/书架等实际新功能、创作恢复、自动派生角色/审稿质量、手动本地/WebDAV备份与非E2E/恢复新副本边界、兼容迁移、已知限制；只写实际完成项。不能宣称所有模型、无限章数、所有文学质量均改善。
5. 按冻结subject内.release/release-profile.json检查**精确资产集合**，当前为7项而不是只看3个installer：读取期望数量/名称/platform/role，逐项回读workflow run-attempt artifact ID、大小、按profile hashPolicy的hash、下载可用性和update metadata的版本/文件/校验引用。缺项/额外旧项/重复项/错误sidecar一律不published-qualified。tag精确subjectSha。签名/公证按profile/ADR0016，允许未签名但必需signing receipt和公开披露，不添加收费签名硬门。正式包只提升GitHub Actions验证的同字节产物，本机包不替代。
6. 遇上传失败保留草稿/已上传清单并停；不换旧产物顶替，不删除旧Release。未发布则交“资格通过/未发布”，不自动执行G02已发布完成关单。
7. artifact保留期过期则回S14D在同subjectSha重新获取完整云端资格/产物/receipt，以新完整hash组为唯一输入；不本机重建、不用旧包。tracked变更回S14A。S14A前由主集成者在现有promotion dry-run/fixture覆盖：当前profile全量通过，漏latest.yml/错blockmap/缺checksum/额外旧资产/过期artifact/tag错SHA均拒绝；R01只运行，不晚改tracked工具。

回退：新schema不原地降级，发布说明提供Classic外观回切与受控数据恢复边界；软件回滚策略依旧C08，不把切皮肤写成回旧版本。

## 执行合同

模型：Sol/high。你不是唯一开发者，不回滚他人修改，禁止再开子代理。只改本片独占文件；共享区仅交一个接线请求给主集成者。先读本包01/04/05、旧通用执行合同及依赖Spec。源路径以开工实际工作树为准；拟新增文件必须登记。状态NOT STARTED，下面是要执行的检查，不是已通过证据。完成给出依赖/最终SHA、实际命令/退出码、证据/未执行项；密钥/作者原稿/本地路径不上传。DSH排除、产品场景仅中文。
