# 不可删减功能并集与逐动作证据

机器入口：[feature-union.json](feature-union.json)。16个能力组内使用逐动作对象：每个action有独立id、实施owner、Writer入口/持久结果/失败结果/fixture/SHA/receipt/status。所有动作requiredInWriter=true且not-run；组状态只能由必需action全通过派生，禁止手写一个组级PASS。不能把一次操作的receipt当整组证据。

S00根据当前生产与donor每个差异文件/交互补齐子动作，记录源SHA/hash/生产consumer。每个已有动作或实际新增功能必须映射一行；无法映射的差异不可直接记“无需移植”。无消费者/占位需源码证据，已实现功能不能为了降低成本改成optional。新发现缺口由主线程分到现有owner并更新manifest，补审后再派发。

## 怎样才算保留

一项功能需同时证明：在Writer可发现的入口→实际handler/store→shared command/typed IPC→持久成果或失败行为→重开/继续操作。每个子动作有独立fixture、被测SHA、evidenceLevel、receipt（可引用同一场景不同step，但必须逐步断言）。U16本地归档/恢复的实施owner为B01，WebDAV/秘密/列表/下载为B02，Writer接线为F04，最终验收为F05；不得用U16组级B02覆盖B01责任。renderer-only/源码/组件/Electron/打包/真实模型分级记录，不能代换；null/NOT RUN不满足放行。

共享业务用同一fixture比Classic/Writer最终命令/参数/持久语义。Writer专属布局/书架/沉浸/新图谱不要求Classic逐像素复制，但旧能力保持且全新共同业务如头像/备份在Classic同服务可达。

头像U10必须包含压缩和全部文件生命周期；图片坏/保存失败可见且旧图还在，不允许删头像避开迁移、性能或回收问题。U16全项目备份保头像与项目资产，U15正文导出仍保持既有格式，两者不同。

F04发现问题先复现，最小修复或复用当前已修实现；写清采用/替换/修复，不以“有Classic备选”“暂时disabled”“这是新功能所以不测”结案。F05 any required Writer action未通过→NO-GO；只可报告已完成子项，整体不能发布为此计划已完成。

本文件是执行验收契约，不是一套新测试平台。153个动作是现有16组功能的断言拆分，可共享场景的不同step，不是153轮模型请求或153套新测试。沿用现有browser/native runner、合成中文fixture和原模型预算；不将每个颜色×按钮×模型全部相乘。

随包提供无第三方依赖的[合同校验器](checks/feature-union-check.mjs)与[反例检查](checks/feature-union-check.test.mjs)，只验证机器清单/门条件，不能证明外部receipt真实或代替产品运行。S00可直接接入既有runner；主集成者仍核对实际入口、SHA和原始证据。
