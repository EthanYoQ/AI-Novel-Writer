## #191：自动补充与作者事实保护不是二选一

Issue 原文要求的是两条不同写路径，不能用现有“粘贴完整角色卡”入口冒充全部完成：

1. **显式资料导入**：作者选择的文本、大纲或世界观可以送入已确认的模型端点，输出待确认角色卡。作者预览、编辑、接受后才写入；拒绝、取消、模型错误、切项目或源资料变化均不落盘。
2. **剧情推进补充**：只允许当前权威定稿触发增量推导。空字段或已有 derived 字段可以按新定稿自动更新派生画像，不要求作者逐项批准；每字段保留 `derived + finalizationId/contentHash/chapterNumber` 来源，且不会升级为作者事实。只有与 author/legacy 字段冲突、角色身份不明确或来源已过期时，才进入待处理提议/拒绝写入。作者可接受为自己的编辑、保留原事实或拒绝。

当前源码已经有可复用基础：导入入口会披露模型端点、提取后确认；角色状态有字段级 `author/derived/legacy` provenance，且 `chapter_progress` 校验定稿来源并拒绝覆盖非 derived 值。但长期身份仍按规范化姓名，不能安全处理同名、改名和别名。计划至少要指定稳定角色 ID 或显式的身份消歧/改名映射；否则“自动新增”会把同名人物合并或把改名人物重复创建。

必须有一个反例验收：作者写明“林岚从未离开北京”，定稿文本被模型误判为“林岚已到上海”。运行后作者字段原值保持，上海只作为带定稿来源的冲突建议；作者拒绝后重开不再成为角色事实。另一个正例证明不存在作者冲突的新物品/伤势会自动更新 derived 字段、幂等保存并追溯至具体定稿版本，无需逐项人工批准。

## #213：最小完整云存档，不扩成云平台

### 真实需求与现有能力

#213 要解决的是台式机/笔记本之间不靠微信手工传文件。报告者把“一书一私有 Gitee 仓库 JSON”作为建议，评论另提 WebDAV；它们不是必须同时实现的产品合同。最小首发可选择 **一个 WebDAV 提供商协议**，只做手动 `立即备份` 与 `从云端恢复为副本`。这已经覆盖跨设备需求，同时避免首版引入任意 Git 命令、代码托管仓库冲突、多用户协作、实时同步、计费或提供商市场。

可复用基础包括项目 manifest/ID、规范化根目录、session lease、外部文件 grant、定稿导出的版本守卫、导入 staging/身份和 SQLite 项目数据。缺口同样明确：现有备份按钮禁用；导出仅有 `merged-md/split-md/txt` 正文格式，不是项目快照；当前没有 WebDAV/Gitee 客户端、OS 凭据保险箱、远端 generation/CAS、全项目一致快照或云恢复 UI。`import-source-identity.secret` 是本地 HMAC key，不得拿来存 WebDAV 密码。

### 最小完整合同

- **资产**：依据迁移计划冻结后的 canonical asset manifest 建快照。至少覆盖项目 manifest、WAL 一致的 SQLite、权威正文/知识/提示词/Skill、恢复候选与账本、头像等业务资产。向量索引若可重建，可明确排除并在恢复后标 stale/rebuild；不可默默遗漏。不得包含模型/API/cloud 凭据、全局配置、绝对路径、日志、缓存、临时文件和旧迁移备份。
- **一致性**：在项目 lease 与源 revision 下创建 staging 快照；SQLite 必须使用 backup/checkpoint 等一致读取，不直接复制活动中的 `db + wal`。快照期间源发生变化则本次不发布 `latest`。
- **远端模型**：本地项目 ID 与 `cloudBookId` 分离；每次上传唯一、不可变 generation 对象和带 SHA-256/大小/schema/资产表的 manifest。完整上传并验证后，才用 ETag/版本条件更新 `latest` 指针。失败的半对象永不被引用，可稍后清理。
- **凭据**：端点/用户名可作为非密配置；密码或 app token 必须由主进程使用 OS-backed secret storage 保存，绝不进入项目、localStorage、日志、诊断、导出或模型上下文。没有可用安全存储时仅允许 session-only，禁止明文降级。默认 HTTPS，并覆盖认证失败、轮换与撤销。
- **冲突**：上传前读取远端 generation/ETag；被另一设备更新时 fail closed，展示本地与远端标识，允许“保留本地”“恢复远端为副本”或重新确认重试，禁止 last-write-wins 和自动内容合并。
- **原稿保护**：恢复先流式下载到 staging，校验大小/哈希/schema/允许路径，拒绝 traversal、symlink/reparse 和未知高版本，再执行迁移验收。默认创建新本地项目 ID，并记录来源 generation；不得覆盖已打开项目或已有目录。失败/取消只删除 staging，不改当前原稿。
- **隐私披露**：首版若没有端到端加密，界面必须明确“内容通过 HTTPS 上传到用户选择的私有 WebDAV，服务端可见；本功能不提供 E2E 加密”，不能以“私有”暗示客户端加密。上传前明确列出范围和估算大小并获得确认。

### 必测失败反例

1. 设备 A 上传 generation 1；A 本地修改并上传 generation 2；设备 B 可分别恢复成新项目，资产 hash/语义一致，且不会复用 A 的本地 projectId。
2. A/B 同时基于 generation 2 上传；后写者得到 CAS 冲突，不能覆盖 generation 3。
3. 备份时作者继续修改、应用崩溃、网络中断或远端只留下部分对象，`latest` 不指向不完整数据，当前项目不变。
4. 恢复遇到错误凭据、超限对象、hash 错误、恶意路径、symlink/reparse、损坏 SQLite、未知 schema 或迁移失败时，拒绝安装且不触碰原稿。
5. 快照扫描证明无 API Key、模型配置、WebDAV token、全局配置、绝对路径、缓存与日志；主进程日志和 renderer localStorage 也不出现凭据。
6. 以打包应用和受控 WebDAV 做两个隔离 profile 的端到端测试；只跑单元测试或本地导出不算完成。公开版本说明协议、非实时同步、冲突策略和加密边界后，才可关闭 #213。

若云存档要进入与现有 modernization 同一 Release，它必须在最终 `subjectSha` 冻结前完成代码、凭据边界、快照资产合同和迁移适配；冻结后再加入网络/存储实现会使同 SHA 资格证据失效。
