# 产品领域词汇与边界

本文是可随仓库发布的稳定领域词汇表。它描述产品中的事实源和边界，不记录单次任务进度、测试数据或本机状态。若本文与已接受 ADR 冲突，以更新或取代该决定的 ADR 为准。

## 产品与项目

- **桌面应用**：本地优先的小说创作编排层，负责项目状态、上下文组织、工作流和落盘。它不提供托管模型、模型额度、在线发布或阅读社区。
- **DeepSeek Harness 插件**：独立发布的早期插件，不读取桌面项目，也不定义桌面应用行为。
- **项目目录**：一部小说的持久化边界。项目会话租约阻止已失效窗口继续写入重新打开的项目。
- **作者事实**：作者明确输入或人工确认的前提、角色、世界观、大纲、蓝图、叙事线索和章节内容。派生视图不得反向覆盖这些事实。
- **派生投影**：可从作者事实重建的摘要、角色状态、连续性信息或剧情树快照。派生失败不得破坏已有事实或上一次成功快照。

## 写作流程

- **结构化角色名单**：角色身份、资料和关系的事实源；角色图谱是由名单生成的只读投影。蓝图可以引用已有角色或提出待确认候选，但不能让无来源的模型推断直接成为角色事实。
- **章节蓝图**：章节写作前的项目事实，描述目标、冲突、事件与相关角色；它不取代结构化角色名单。
- **草稿、审稿、修稿、定稿**：草稿可生成多个版本；审稿意见经人工确认后才成为修稿输入；修订稿经差异确认后合并；定稿是项目内提交，不等同于对外发布作品。
- **叙事线索与伏笔**：作者可确认的长期叙事计划和事件。它们参与后续上下文时仍受项目事实、章节范围和预算约束。
- **剧情树**：从大纲、蓝图、定稿摘要和已确认叙事资料归纳的只读派生快照，只用于展示进度和打开来源，不参与正文提示词，也不成为第二套剧情事实。

## 模型、语言与提示词

- **界面语言**与**项目写作语言**相互独立。模型指令应跟随项目写作语言，作者原文和引用资料保持原样。
- **提示词合同**：语言、结构化输出、工具协议和数据安全约定不可由用户或 Skill 覆盖；创作角色定位和任务指导可以按中英文、全局或项目范围定制。
- **写作 Skill**：按设定与规划、章节正文、AI 审稿、修稿与定稿前润色阶段绑定的补充指导。工作流启动时冻结当次内容，不能覆盖作者事实、写作语言或提示词合同。
- **创作策略**与**供应商推理强度**不是同一个概念。前者表达写作取向；后者只在模型支持时映射到提供商参数。

## 发布与更新

- **正式版本源**：GitHub 最新正式 Release。精确平台、资产、保留期和签名披露由 [`.release/release-profile.json`](../.release/release-profile.json) 维护。
- **更新检查**：只有成功取得最新正式版信息后，才记录当天已检查。网络失败不会消耗下一次启动的重试机会。
- **Windows 更新动作**：发现新版后先提醒；用户明确点击下载后才下载，完成后再由用户选择是否重启安装。
- **macOS 更新动作**：发现新版后提醒并打开固定的官方 Release 页面；应用不在内部下载或替换 macOS 程序。
