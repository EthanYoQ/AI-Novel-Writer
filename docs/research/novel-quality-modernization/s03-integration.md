# S03 启动与全局数据接线

依赖 S02 `d72c13db638f1f2d87db3230e985411566139fca`、F01 `e2af35966adae4754b18ac7553544a618fa3dc34`。F02 展示组件另在 `c7446e5ecb63e4c912e7b09a2620bdd89ee84280` 提交，未作为完整 Writer 业务验收。

## 行为

沿用原应用单实例身份和用户数据目录。主进程取得锁后，用同一 generation 迁移全局配置和模型，验证皮肤状态，再注册普通业务接口。迁移失败只打开可关闭的诊断窗口；同 ID 凭据冲突只显示“凭据不同”，不输出模型 ID、密钥或其 hash。全局 disposition、恢复边界及未知内容保留策略见 [领域合同](s03-global-data-contract.md)。

renderer 保持原 file origin 和 localStorage，按 MainReady → 皮肤快照 → 外观写入及读回 → main acknowledgement → 再次读回的顺序加载 App。main 校验主窗口、主 frame、完整文档 URL、generation、皮肤 revision 和单调 profile revision。旧外观键和无关选择保持原字节；启动后外观存储失败不卸载已有编辑器。未加载工作台时由启动页响应关闭，工作台挂载后移交原未保存正文守卫。

Windows/macOS 安装和升级探针显式传递互不相交的 legacy、canonical、userData 根。已有旧版本 alias 保留。升级后只接受合法 completed receipt 指向的 generation，不回退读取旧根；旧根原有保留断言继续执行。Windows PowerShell 5.1 入口保留 UTF-8 BOM。macOS 独立 vector Node runner 保持其原执行方式，未冒充主进程启动。

- `scripts/global-startup-acceptance.mjs` 使用六个合成隔离目录，在实际 Electron 41.10.7 运行四场景通过：旧根迁移及同 generation 重启、损坏源阻塞、凭据冲突阻塞、损坏 renderer 偏好保留与显式关闭。验证旧偏好字节、字体/颜色/缩放、无关模型选择保留；旧源后来损坏不会回灌。未打开真实作者项目，物理模型调用 0。
- 四组旧文件授权/import 测试因缺少全局准入而在错误文案阶段提前失败。仅补实际 coordinator 的合成夹具，原权限、路径与字节断言不变，48/48 通过。中央相邻六套增量共 56/56 独立通过。
- 资格脚本相邻套件首次 97 通过、1 项旧环境列表断言失败；补齐两个新变量后该套 12/12 独立通过。语法、编码与隔离根拒绝测试另有独立证据。此前云端 `3c14cad6a2d5551bef2ed7c9f9c833e48b93254c` 的唯一 Node 失败为固定端口旧断言，现随操作系统分配端口的实现同步修正。
