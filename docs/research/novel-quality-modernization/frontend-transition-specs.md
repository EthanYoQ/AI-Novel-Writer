- 最终保留 153 个 action 的用户能力。布局措辞可映射为 V3 等效交互，不能删能力；在同一执行覆盖记录中记 action ID、新入口、当前业务 owner、证据与缺口。不是 153 次进程启动、截图或独立脚本。

## 核心可交接里程碑

1. 接续现有 F03/B01/B02/S12 及线程四的核心修复，不重写已完成模块。按实际 HEAD 和检查点，将失败分成业务、UI/driver、fixture/ABI、未定位。重点包括 U13 正文/历史/印章终态，以及 Windows native 并发崩溃历史；未知问题不能归为“换壳自然解决”。
2. 对受影响的生成/取消/候选恢复/审稿修稿定稿、保存失败与并发编辑、导入、归档/WebDAV 恢复，复用已有生产 command/IPC/main/repository 测试和回执。相关变动定向复验；未变且条件相同的证据沿用。合成 provider 不证明文学质量。
3. 不存在未处置的可达核心数据丢失、越权或持久状态错误。仅最终平台层未验项明确交 S14C/D，不能假称已修；已知 native 问题仍阻断受影响平台的最终资格。
4. 将当前项目 transition/save owner、生成命令/订阅、稳定角色 ID 和备份接口的实际接缝交 F04；用现有路径记录即可，不新建通用 adapter 框架。

通过只表示核心可供接入。最终 UI、文学实验、升级与三平台资格仍须完成；不能写整体完成或以此关闭用户问题。

## F04 — V3 接入（局部重开）

替代原 F04 的当前 Writer 布局实现要求。既有头像、只读书架、连续性、备份与共享业务修复保留。F01 偏好兼容、F02 样式/资产仅复验换壳影响，不整片重开。

**所有权**：一个前端 owner 负责 `src/components/layout/v2/`、`src/components/pages/v2/`、受影响页面呈现、`src/styles/redesign/` 及实际移入的 magazine 样式/资源。主集成者独占 App/main、appearance stores/profile、中央 IPC 与 package/lock。核心 Bug 归其业务 owner。不得按整个目录覆盖 donor。

**薄切片**：固定 donor 并显式 V3，取得书架、编辑、角色、设置参考截图，记录 viewport/缩放/字体；保留资源来源与许可。先由 V3 外壳承载当前核心的“打开/新建→编辑→保存→重开”。保留稳定 React owner/key、dirty/undo、任务和项目切换保护，使用隔离合成项目。

**一次视觉确认**：由用户确认薄切片的整体布局和字体方向。等待期间可继续独立核心工作，不铺开全部页面、不做整套新壳资格。此确认不扩展为每个组件重新请求设计批准。不能拿不同内容状态的截图作逐像素结论。

**完整接入**：确认后按现有功能组接入当前 command/IPC、角色稳定 ID、生成/恢复、保存、图谱、头像、备份、设置。旧版页眉/首字下沉等视觉形式以选定 V3 对应呈现为准；编辑/预览/中文输入/保存/导航等能力不减。资源许可缺口只针对实际引入资产处理，不重审所有依赖。

**出口**：功能组均有真实 V3 入口；CSS 层叠、portal、菜单/tooltip、字体、窄栏换行与遮挡可用；视觉未被后续接线推翻；无跨项目串状态、稿件丢失或假按钮。按行为切片审查，不另建像素门禁平台。

## S14C — 升级与中断恢复
