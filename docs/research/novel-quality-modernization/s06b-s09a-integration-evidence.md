## 正文与知识源

1. 默认正文入口先取得主进程签发的准备凭据。主进程在异步读取知识库前后检查 SQLite、模板、写作 Skill、项目 Markdown 指导与原已选草稿；开始生成时再次比较。renderer 不能提交自行构造的知识库快照。
2. 准备快照保留实际文档 ID、片段 ID、原文 hash、完整文档片段集合与 LanceDB 版本。向量命中必须对应真实 canonical 片段；不按文件名或相同文字猜身份。当前模型没有匹配的向量空间时可以使用 canonical 文本检索，损坏或无法证明的空间仍拒绝。
3. 已归档的较高版本不能遮住仍合法的前章。准备时明确选中的源身份不能在开始时移除，原 revision/hash 也必须一致。正文只允许选择目标章之前的承接来源；异步步骤中发现变更不创建新 root。
4. 正文保存由主进程在同一 SQLite 事务内核验原始来源、明确可见组合、字数与目标章，再创建草稿版本和保存回执。renderer 不再分别取版本号、创建正文。`length` 片段即使显示为未完成，也只有在主进程明确给出 `compositionEligible` 后才可用于组合。
5. 恢复复用原知识库快照与查询，包括作者附加检索词；不重新检索。前章正文只来自主进程核验后的 `selectedDrafts`。已保存回执可以在原来源后来改变或消失后只读取回，不再 resume、组合或创建版本。
6. 重启先完成新运行的来源检查，再取消旧运行；准备被拒绝不会取消原 root。原始 artifacts 始终保留，组合文本不会覆盖它们。

知识库共享 gate 覆盖 14 个公开读写入口及同步关闭/迁移 fence 的占用检查。验证与 SQLite 正式写入在同一短 gate 内；模型调用不长期持有它。该约束协调当前进程的操作，不等于外部进程排他锁或 LanceDB/SQLite 跨库事务。

## 角色提案

- 架构、目录、资料提取和导入的角色结果先持久化为提案，保留模型原始数据与确切生成/导入来源。
- 作者明确选择新建、关联现有身份或保留未采用项；同名不会自动合并，关系两端必须明确选择。采用依赖当前角色 roster revision、来源证明与既有 ID 写入事务。
- 目录绑定具体同步 operation。蓝图、core、模板等正式依据后来改变时，旧提案仍可读，但拒绝写入。源证明省略可选字段时保持可重读的稳定编码。
- 导入全局事实与角色提案同事务提交；只有具备实际来源证明的导入结果可以采用。未证明的旧导入/旧资料保留可读状态，其迁移恢复仍由 S06D 接续。
- workflow store 在执行采用前等待作者确认。自动模式也不能代替作者采用；取消或重复确认不会重复执行身份写入。
