# 中文连续性检查器：第一轮校准

日期：2026-09-08。用户批准研究建议后执行一次检查器校准；不是新的十轮修复循环。

## 范围与固定点

- 生产源码起点：b96e102657a462b13e579bf2d98cd263e879fd84。
- 本轮仅新增实验用提示/引用校验纯函数、离线 runner 与针对性中文测试。
- 不修改自动定稿、写作 prompt、角色状态、数据库、UI、provider 配置和发布流程。
- 不改真实小说；保留已有失败样本，不让本轮候选影响后章记忆。
- 普通审稿臂复用当前中文内置 consistency_check 模板及 ReviewPromptBuilder；定向臂检查关键状态、时间条件、知情、本章到期目标，并要求可定位证据。两臂输入材料相同。
- 原稿仅用于修订前后对比，不是另一章历史。未来计划不是已发生事实。作者明确事实优先，但不能以尚未实现的蓝图状态覆盖实际前史。

## 实验

10 个预冻结案例，双臂共最多 20 次物理请求，每案例每臂 1 次，没有语义重试或改稿。模型使用本机已授权的硅基流动 DeepSeek-V4-Flash，同温度和输出上限；请求参数写入无密钥收据，配置不改动。

样本包括 4 个历史完整问题正文、3 个历史正确片段、2 个受控正确反例和 1 个缺少中间历史的证据不足反例。其中历史问题经独立预审分为 2 个确定负例、2 个无依据断言/待核实风险，不混算成 4 个确定矛盾。开发集 3 例、保留集 7 例；重叠的 R10 正文放在同一组，两个集合都在请求前冻结。本轮不根据输出继续调整提示词。同一案例两臂成对并发（最多 2 请求同时进行），不同案例顺序处理；仅收据序号按案例交替分配，不保证网络启动或完成次序。不用被测模型自评分裁决胜负。

这些仍是相关的小样本：部分案例使用同一小说背景，问题正文较长、正确控制多为短片段。保留集不是独立新小说分布，不以分组命中率宣称长篇泛化或两类案例难度相同。

inputs.json 仅含 id 和 packet；gold.json 独立，runner 不得读取、发送或利用 gold 评分。原始完整小说证据位于 ignored 本地实验目录，不进入公共代码提交。

## 判定规则

- 引用可定位只证明字面存在，不证明语义判断正确。
- clear 仅表示没有发现问题；格式错误、引用错误、超时、截断不视为 clear，也不能从分母剔除。
- 负例必须指出预标注的具体关键错误，不能靠报告任意小问题充作命中。
- 风险例只要求指出当前证据不足以支持的变化；接受 unknown 或核实建议，不要求宣判逻辑不可能。未知编号可前后重复，缺失的中间历史也不能被擅自断言为“未发生”。
- 正例允许合理省略、间接转交、角色说谎、未来安排和未确诊状态；不能为了降低漏判而一律报错。
- 证据不足须保持限制可见，不编造缺失章节中的交接，不把信息缺失宣判成事实冲突。
- 对新增但确有依据的发现另行裁决，不能因为 gold 未列出就自动当误报。
- 本轮不评字数控制与文学自然度收益，不生成修订正文。对旧修订新增错误的识别，不等于新的局部修订机制已验证。
- 分开报告机械有效性、关键错误命中/漏判、误报、无依据断言、未知、请求成本；开发/保留集分开。

## 接入边界

即使本轮优于普通审稿，也只构成小样本校准信号，不直接接入自动定稿。下一阶段才考虑经过审查的局部候选流程和真实较长中文续写；未运行的生产验收、安装包资格及发布检查不得标通过。

## 安全与可复跑

runner 默认只准备请求；只有显式 execute 才联网。模型配置只读，密钥仅用于内存请求头；不落盘、不打印原始配置或 provider 错误体。每次请求先记收据再发送，保留输出/失败状态；不隐式重试。输出必须是仓库内 runtime cache 的新目录，拒绝覆盖旧结果。
