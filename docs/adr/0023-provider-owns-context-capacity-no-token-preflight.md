# 发送前不按自估 token 拒绝，上下文容量交给服务商判定

2026-10-25 由维护者决定（讨论区 #77）：生成不再用我们自己的 token 估算卡住请求，长度只靠写进提示词的软性字数引导。账本照常记账，只去掉拒绝。

## 背景

讨论区 #77 的作者用 DeepSeek 官方 deepseek-v4-flash，在模型设置里把上下文窗口填成 65,536。第 9 章写稿的首个请求在发送前就报 `TASK_BUDGET_CAPACITY_CONFLICT`。

- 输入上界按 UTF-8 字节计，中文每字记 3。同一段提示词实测 `prompt_tokens` 为 17,384，字节上界是 71,608，高估 4.12 倍。
- 这个上界再叠加作者填的上下文窗口、根账剩余 token liability，任何一项不够就在发送前拒绝；审稿与定稿后处理走另一分支，报 `GENERATION_INPUT_CAPACITY_EXCEEDED`。
- 实际只占 64K 的约 29%，是误拒。

维护者原话（摘）：生成大纲、蓝图这些环节不需要加 token 限制，开了思考后用量不固定；大纲和蓝图要有字数要求，例如用户填 600 字就生成 600 字左右，但这不是硬门槛。对四条修法与次数刹车的答复是「都确认」。

## 决定

1. **发送前不按自估 token 拒绝。** 提示词是否放得下由服务商判定。服务商返回上下文超长时，运行以 `GENERATION_CONTEXT_LENGTH_EXCEEDED` 失败，界面说明提示词超出模型能接受的长度，建议换用上下文更长的模型、调低最大输出 Tokens，或精简本章要求与参考材料（OpenAI 兼容服务商把输入与 max_tokens 合计计入上下文，硅基流动在 max_tokens 本身超过上下文时同样拒绝）。作者的「上下文窗口」设置不再影响发送，文案不指向它（2026-10-26 维护者确认）。识别规则按 2026-10-25 实测的 DeepSeek 官方与硅基流动 400 错误体写成（`electron/llm/provider-context-length.ts`）；Gemini 的规则没有实测。
2. **输出上限只取模型或作者设置。** 发给服务商的 `max_tokens` / `max_completion_tokens` / `maxOutputTokens` 取已验证预设的模型最大输出、作者的「最大输出 Tokens」与根账单次输出上限中的最小值。新根的单次上限本身就是前两者的最小值，旧根保留冻结时的 32,768。输入估计、上下文窗口、根账剩余额度都不再收窄输出。开了思考时不替它预估。
3. **字数是软性引导。** 大纲、蓝图、正文的目标字数继续写进提示词，正文按目标字数只发一次请求，不再按语义估算切分或拒绝。结构化条目（蓝图批次）在输出上限放不下全部条目时仍按条目切分，切分只由输出上限决定。
4. **记账照常，只去掉拒绝。** 每次调用仍先预留再结算：预留 = 输入上界 + 输出上限 + 推理预留 + 安全余量，usage 如实结算。以下拒绝点删除：
   - 规划器按上下文窗口、根账剩余额度收窄输出与 `capacity-conflict` 决策（`TASK_BUDGET_CAPACITY_CONFLICT`）。
   - 无语义需求分支的 `GENERATION_INPUT_CAPACITY_EXCEEDED`。
   - 规划层与预留事务里按 `maxTokenLiability` 判的 `ROOT_BUDGET_EXHAUSTED`。
   - 短细纲重试可用性里的 token liability 条件。
   - 结算时实际用量超过预留就阻断根的 `USAGE_EXCEEDED_RESERVATION`。

字节估算继续作为预留里的输入项，`estimatorVersion` 与账本表结构、receipt 格式不变；`maxTokenLiability` 字段保留在根策略里，只记录、不判定。

## 保留的刹车

- 每个根最多 32 次物理请求（批量根按章放大）。达到后仍报 `ROOT_BUDGET_EXHAUSTED`。
- 活动时长上限 `maxActiveElapsedMs`。它按时间不按 token，维护者没有要求去掉。
- 未知结果不自动重发同一 attempt，取消与恢复语义不变。上下文超长的失败也不自动重试：同一请求重发必然再被拒。

## 与受审规划的关系

`docs/plans/novel-quality-modernization/03-CONTRACTS-AND-GATES.md` 的契约 C01 第 11–15 行要求：根账限制输入+输出总 token liability；预留不少于输入估计上界加协议最大输出；实际超估计停止后续请求；`BudgetPolicy` 用输入估计、上下文余量与父剩余额选值；输入过长先减材料或拆任务。本 ADR 取代其中以 token 数为依据的拒绝与停发：token liability 只记录，超估计不停发，输入估计不参与选值与是否发送。物理请求数与 elapsed 两项刹车、预留与结算的事务、未知结果保护照旧。

照 ADR-0019 的做法，**未改写受审规划字节**，`docs/plans/**` 本次 diff 为 0，取代关系只记在本 ADR。ADR-0019 去掉的是实验 runner 的总调用帽，本 ADR 去掉的是产品里按 token 的拒绝；两者都是「移除拒绝，保留记账」。

## 风险与缓解

- **服务商以超长拒绝时，这次请求已经发出。** 实测 DeepSeek 与硅基流动的 400 响应不带 usage，账本按预留保守记这一次；失败不自动重试，卡片建议换模型、调低最大输出或精简材料。
- **作者填的上下文窗口不再生效。** 设置项保留，模型识别仍会写入它；它只用于模型设置页的提示和根策略里的记录值，真正的上限由服务商执行。
- **思考或超长输入的实际用量可能超过预留。** 实际用量照实记入账本、不截平，次数与时长刹车仍限制失控的重试循环。
- **旧根上的正文请求改为按输出上限整段发出。** 旧策略下按语义估算设的输出上限（例如短细纲 1,712）不再使用；冻结策略的字节与哈希不变，恢复不受影响。
