# Program v3 交付执行规则

本文件只管当前执行方式。范围、依赖和验收以[现行交付 delta](../research/novel-quality-modernization/delivery-contract-delta-2026-09-21.md)及其未被替代的冻结合同为准；任务状态以唯一私有检查点为准。

- 主线程控制范围、共享入口、集成、审查和发布决策。`/implement` 按可独立验证的行为切片交给子 Agent；每片明确目标、验收和文件所有权，并按承接任务**显式指定**模型与思考强度，不默认继承主线程的 Sol/High。子 Agent 禁用 Astra、Terra，可在 Sol、Luna 中按复杂度选择；子 Agent 不再派子 Agent，也不覆盖他人改动。实施及审查使用 `ponytail full`，优先复用共同入口和现有 fixture。
- 每片一次独立代码审查；修复只复验原 finding 与受影响回归。最终审查关注跨片组合风险和未覆盖差异。阻断项须给出可达触发条件及作品丢失、安全、当前合同或验收真实性影响；额外覆盖或可选重构不自动阻断。
- 全部功能动作必须有可定位断言。共用真实旅程、进程、项目和回执；普通展示与导航使用真实组件浏览器证据，IPC、持久化、文件授权、恢复、凭据、IME、窗口和原生模块使用相应 Electron/安装版证据。合成 provider 不冒充真实模型。相同代码、配置和环境的有效检查可复用。
- Writer 是最终产品唯一主界面。普通功能测试与演示先在隔离 profile 明确选择 Writer，并在动作前断言当前 shell；旧默认和旧偏好仅在专门迁移场景验证，不计作 Writer 动作。测试选择不提前激活正式发布默认值。Classic 历史 baseline 只在独立环境保留，不新增 Classic 专属功能或全面双壳验收；S13 保留必要迁移和共享业务。
- 根据实际消费者判定改动的重验范围。沿用证据保留原 `testedSha`、列出其后相关差异及沿用理由；纯文档改动不触发产品实验。新构建仍验证自身来源、安装、启动及 hash。历史失败、旧回执和账本不改写。
- 同一根因两轮明确假设的修复仍失败，准备最小复现、预期/实际、实际 SHA 和已尝试方案，作一次有界根因咨询；连接或外发授权不具备时继续本地诊断，可用非 Astra 独立顾问。必要时 `yq-simplify-code` 只审失败链路，最多三项有证据的调整，再定唯一下一步。真实阻断继续修复或如实 `BLOCKED`，不能放行依赖项。
- 新增抽象、测试或门禁须有独有的实际失败风险。保留作者作品、授权路径、外来归档、凭据及恢复的保护。只维护唯一当前检查点，分开记录实现、验收、提交、发布；按确认路径暂存。公开推送前检查私人内容，合并、标签、发布遵守明确授权。
