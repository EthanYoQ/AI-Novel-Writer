# Program v3 交付执行规则

全部 34 项范围先读[现行 Spec 索引](../research/novel-quality-modernization/current-spec-index.md)，再读各原 Spec、适用修订及[实施计划](../research/novel-quality-modernization/frontend-transition-plan.md)；本轮产品切片、新资格和工作顺序由[线程 10 交付计划](../research/novel-quality-modernization/thread10-delivery-plan.md)拥有，替代关系见[交付 delta](../research/novel-quality-modernization/delivery-contract-delta-2026-09-21.md)。新要求已生效，机器接线待实现；任务状态只读唯一私有检查点。

- 顾问负责产品范围、合同与计划；执行主线程负责实现细节、共享接线、集成和交付。改变视觉来源、功能/数据/质量标准或发布范围提交具体差异，不能自行重做总计划。
- 实施按可独立验证行为切片派工；每片明确目标、验收和文件所有权。按 2026-10-01 用户决定，所有新建开发与审查子 Agent 默认继承主线程的模型和推理强度：调用 `spawn_agent` 时省略 `model`、`reasoning_effort`，不按任务类型固定 Sol/Luna/Astra，也不使用固定另一模型的角色覆盖。仅用户后续明确指定时才覆盖；本条取代此前显式指定模型/强度、固定版本、模型禁令和强度下限。`fork_turns` 只按上下文需要选择，独立审查可用 `"none"`，不与模型选择绑定。子 Agent 不再派生、不覆盖他人修改，最多同时两个实施 owner 并预留独立审查。
- 已运行子 Agent 不因本次规则变化中断或重建；`followup_task` 继续原 Agent 的已有配置，不宣称会重新继承主线程后来的配置。运行元数据可获得时随实际任务记录，不可见则标未验证，不另派空任务或新增模型验证门禁。续派仍明确文件所有权和验收，实施者不能自审；不借新用户线程绕过名额。
- Superpowers 对所有模型按各 Skill 自身触发条件使用；不因规格已接受、项目约定或模型类型跳过所需的 brainstorming、writing-plans 等步骤。现行计划仍是产品范围与依赖依据，不另建平行总计划；Skill 不扩大外发、发布或产品验收授权。此项目存放路径与用户明确授权仍有效。
- 实施/审查使用 ponytail full。一次行为切片一次独立审查，修复只复验 finding 与受影响回归；在满足适用 Skill 要求的前提下合并规格与代码质量检查，不为同一变化叠加同义审查。最终审查关注组合风险，不重开无新反例关闭项。
- 调试先复现、核验代码/driver/ABI/profile/输入，再定位首个错误边界，提出一个可验证假设并最小修复；不循环增加 sleep、同时改多层或把测试夹具失败当产品缺陷。两轮同根因失败升级为本地有界根因审计，只审当前失败链并确定唯一下一步；真实阻断继续修复或如实登记，不跳过。用户已放弃 Codex-with-ChatGPT 配置与咨询依赖，本条取代旧约定中的强制 C2C 咨询，不重启该配置或以外部咨询阻塞本地工作。
- 最终唯一呈现为固定 donor V3 时尚杂志，逻辑 shell=writer；当前弃用 Writer 不再追加视觉修补与全量 UI 资格。核心可交接不等于最终 UI/发布；新外壳先薄切片用户确认，后完整接入。不能整体合 donor 后端，不能删共享能力。
- 多动作共用旅程/环境/回执，普通 UI browser，OS/native/权限/恢复用有效真环境。旧核心证据可按差异沿用，旧 UI 不代新入口。原生 ABI 切换在共享 worktree 串行；独立环境才并行运行。
- 阻断须有可达触发和当前合同、数据、安全或验收真实性影响。新增抽象/测试/门禁须说明独立失败风险；可选优化不阻塞。保留作品、授权、凭据、备份恢复保护，不无限追逐同账户攻击者理论窗口。
- 保留实际 testedSha、失败、账本和明确沿用理由；新包有自己的准确来源/资格。纯文档不重跑产品实验，达到工作包出口即推进。
- 原生接线检查和正式实验沿用唯一物理账本；线程 10 的有界 API 筛选使用独立开发日志，不能手写正式账本或借已关闭 diagnostic 额度。文学评审按案一次评完整闭环，仅仲裁分歧，不叠三阶段双评或额外全绿彩排。
- 只维护唯一当前检查点；分开实现、验证、提交、发布。精确暂存，检查待公开历史的私有资料；Draft 推送、merge/tag/release、外发咨询和 Issue 写操作分别服从实际授权。未知授权不虚构，也不阻止独立本地工作。
