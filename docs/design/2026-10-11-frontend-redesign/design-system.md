## 设计理念

这是一个写小说的工具。界面应该像一本排版讲究的书，而不是控制台：

- **正文是主角。** 正文以纸面呈现，衬线字体，每行约 34 字，两端留白。其余界面都退后。
- **墨与纸，加一种颜色。** 界面几乎只有墨色与纸色。黛蓝是唯一的强调色，只标记三件事：主操作、当前位置、键盘焦点。
- **顺序可见。** 流程脊自上而下的排列就是真实的创作顺序，状态标记（完成、进度环、未开始）说明每一步走到哪里。
- **克制的动效。** 只在状态变化时动：侧页滑入、弹层浮现、进度推进。没有循环装饰动画。

## 材质：按钮、浮层与提示

2026-10-14 用户评审 RD-4 后确定（设计竞技场的合成稿「压印·浮笺」、按钮方案 C、提示方案「朱批」）。一句话：可按的从纸面凸起，可写的凹进纸面，浮在纸上的都是同一张笺，印在纸上的是字。

- **按钮受光。** 主按钮是压印块：1px 外沿、更深的底边、顶沿一线受光、一片带黛蓝色相的投影。次按钮是纸片：侧沿与上沿刚过 3:1，底沿更深，底下贴一线墨。主按钮与次按钮允许不超过 2% 的同色相纵向受光（`linear-gradient` 两端只差 1 到 2 个明度点）。这是全应用唯一允许的渐变，不得用于其他元素，不得有彩色渐变、光泽带或玻璃效果。按下时下沉 1px，受光撤掉，投影收成内凹；指针停在按钮上按下时按下态压过悬停态（悬停规则排除 `:active` 与展开态），主按钮与危险实心的按下色比悬停色更深；次按钮按下换成 `--paper-press`，比纸面（悬停时的底色）更深，浅色取 `--surface-2`，深色往 `--frame` 方向压（深色的 `--surface-2` 比纸面亮，不能用）。渐变两端随悬停与按下换色，与底色、投影、位移同步 140ms 过渡，不瞬切。减少动态效果设置下按下不下沉、不缩小，只留颜色与内凹。
- **危险按钮是平的方肩朱印。** 4px 圆角、单线框，不受光、不投影、不下沉。外形本身与压印块不同，去掉颜色也能区分（第 8 条）。
- **禁用是没上墨的平面。** 墨色薄雾底、`--ink-3` 字、撤掉全部材质，不用 `opacity`。勾选框、开关与输入框同一规则：禁用的开关开着也撤掉强调色，轨道是墨色薄雾，开关状态只由滑块位置说出。危险分组里的禁用菜单项悬停也不出朱色底。加载中照旧禁用，再加 `aria-busy="true"`，按钮外观不变（悬停也不变），底沿画一道墨线；按钮文案同时改成进行时，例如「清除中…」。
- **输入框是凹槽。** 灰槽底，整圈 `--edge`，底沿不加深，与次按钮的纸片区分。
- **浮层统一材质。** 菜单、弹层、通知、对话框都是 `--layer`（等于纸面），层级越高越亮。小浮层用 `--shadow-pop`，对话框用 `--shadow-dialog`。对话框底栏落在桌沿 `--surface` 上，标题衬线、恒为墨色。菜单不做进场动画，弹层 140ms 浮现。
- **提示条与后果说明是朱批。** 没有底色、描边和圆角，不加左侧色条。语气只由页边一枚 16px 线描符号说出，颜色加外形两条通道：圆 i 信息、圆勾完成、三角提醒、八角危险或失败。标题用 Noto Serif SC 14px，动作排在文字下方并与文字左对齐。危险确认里「能否恢复」那一句用朱色衬线字（`.pi-dialog-recover`），只排这一句，建议与说明另起一句用墨色。
- **语气色排正文只限白名单。** 语气符号本身、`.pi-dialog-recover`（危险确认里能否恢复那一句）、`.pi-inline-confirm-text`（就地确认的后果句）、`.run-step-error`（运行步骤的失败原因）、`.run-badge`（运行状态徽记）。其余正文一律 `--ink` 或 `--ink-2`，新增一处要先改这条。
- **三种标题三种字。** 通知标题是消息，用 UI 无衬线 13px、500；提示条标题用衬线 14px；对话框标题用衬线 20px。
- **提示栈。** `toast` 与 `actionToast` 进右下角同一个栈：新的在下，鼠标停在栈上时所有计时暂停。每条通知一到就露面，不在暗处排队。常驻（`duration: 0`）、出错、带动作的通知从不让位，也不受条数上限约束；4 条上限只约束普通通知：新来的占一个名额，常驻、出错、带动作的各占一个，剩下的名额不够时把已有的普通通知挤掉（播退场后拿掉），让位顺序是已过期（暂停期间超过时长）、完成与信息、提醒。重要通知很多时栈最高到顶栏以下（上沿留 48px，窗口的最小化与关闭按钮仍点得到），再多就在栈内滚动：新到一条时滚到底让它露面，往上滚能点到最早那条的关闭；栈没满时不是滚动容器，不裁卡片投影。同一句话再来一次不新起一条，原来那条重新计时。增删一条时其余卡片从旧位置滑到新位置。动作回调失败时通知照样关闭，失败原因作为一条出错通知进栈。栈画在模态之上，对话框开着时点通知不会关掉对话框；栈的挂载点是 `aria-live="polite"`，模态开着时到达的通知读屏也读得到；卡片自身不带 `role` 或 `aria-live`，每条只经这一个通道播报，不会读两遍。模态给 `body` 设 `pointer-events: none` 时栈显式接回指针，卡片间空隙照样暂停计时。
- **命令式弹窗。** `alertError()`、`confirm()` 的签名不变，渲染进 body 下带 `.paper-ink` 与 `data-theme` 的宿主，跟随主题。`confirm({ danger: true })` 进场焦点落在「取消」上。关掉时 140ms 淡出，淡完才 resolve。

## 规则与验收标准

“获奖品质”无法直接审查，下面每一条都可以由审查者逐项核对。

**结构**

1. 主导航只有四个创作阶段，按创作顺序自上而下排列，每项显示状态。
2. 每个功能只有一个规范入口（对照 `feature-matrix.md` 的落位表）。
3. 每个交互层只有一个主按钮，它是流程上的下一步。对话框是独立的交互层；拆分主按钮（主按钮加下拉箭头）算一个。没有流程下一步的页面（诊断、外观设置）可以没有主按钮。
4. 写作此章不再弹出重复蓝图字段的表单。

**视觉**

5. 一个视觉概念，没有装饰性叠加层：没有水印数字、彩带、分区色条。
6. `src/components` 中没有十六进制、rgb、hsl 颜色字面量；只有一层颜色令牌。
7. 强调色与危险色、提醒色、完成色色相不同。
8. 危险操作与主操作外形不同（描边红字或实心红色，从不使用强调色）。
9. 浅色与深色下，普通字号的文字（说明文字也算）与背景对比度不低于 WCAG AA 的 4.5:1；大字号文字（24px 起，或 18.66px 起且粗体）与图标、边线等非文字元素不低于 3:1。说明文字（用时、时间戳、待执行与跳过的步骤、字段注释）用 `--ink-3`，它在外框、面板、悬停底、纸面上都过 4.5:1；落在比这些更深的底上（例如选中行的 `--accent-soft`）时改用 `--ink-2`。不得用 `--ink-4`：`--ink-4` 在外框、面板、纸面上都不到 3:1，只用于占位符、分隔与装饰。禁用控件的字也是 `--ink-3`，落在墨色薄雾底上可能低于 4.5:1，WCAG 1.4.3 不要求禁用控件的对比度。相邻两级墨色（`--ink` 与 `--ink-2`、`--ink-2` 与 `--ink-3`、`--ink-3` 与 `--ink-4`）在同一底上的对比度至少差 1.25 倍，层级不能压平。
10. 只有一个按钮组件；不出现原生 `<button>` 直接带样式。

**交互**

11. 所有危险操作都有确认，并写明后果和能否恢复。不可逆且影响作品数据的操作用危险确认对话框；删除整部作品还要输入作品名。侧页内影响较小的操作（清空日志、放弃一条恢复候选）可以用就地确认条。
12. 所有空状态都经过设计：标题、说明、一个动作。
13. 所有可编辑页面都响应 ⌘S / Ctrl+S；⌘W 关闭当前标签；⌘P 查找章节。
14. 键盘可以到达每个控件，焦点环清晰可见。
15. 动效只出现在状态变化上，并尊重“减少动态效果”设置。

**语言**

16. 创作界面不出现实现术语（LanceDB、FTS、BM25、Embedding、向量、query、MCP、token）。例外：token 只用作模型设置“最大输出 Tokens”这一项的名字，以及请作者去调它的提示；其余地方（含诊断、运行侧页）不出现。
17. 同一对象全应用只有一个名字（例如“备份”只叫“项目备份”）。
18. 样式选择器不依赖元素位置、工具类名组合或本地化文字。中英文界面都通过 `pnpm check:i18n`。
